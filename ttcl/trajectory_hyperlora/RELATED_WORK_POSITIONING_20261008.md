# 轨迹生成在线 LoRA：截至 2026-10-08 的相关工作与可证主张

本审计只依据下列论文原文及当前本地实验。**“把文本／轨迹变成 LoRA”“推理时在线改变参数”“逐次维护 LoRA”“LoRA 矩阵几何影响行为”均已有直接相关工作，不能分别当作本项目的独立新颖性。** 可投稿的主张必须落在一个被公平对照验证的具体算法与能力上；目前连续写入超过固定首条、方法自身闭环、多题序官方评测仍未证明。

| 工作 | 已公开的方法与评测 | 对本项目的约束 |
|---|---|---|
| [Text-to-LoRA](https://arxiv.org/abs/2506.06105) | 从任务文字描述一次生成适配器，训练利用已有任务适配器。 | “超网络生成 LoRA”本身不是贡献。 |
| [SHINE](https://arxiv.org/abs/2602.06358) | 将上下文单次映射为 LoRA，让后续问答不再直接读取原上下文。 | “上下文压成参数且推理不重读”也不是贡献。 |
| [LatentSkill](https://arxiv.org/html/2606.06087v3) | 输入**文本技能文档**生成 LoRA；先做文档预训练，再用教师代理轨迹监督生成器；报告 ALFWorld。 | 我们需要与技能文本／原始轨迹提示公平比较，并证明直接从**自身环境反馈轨迹**学习，而不只是重复其文本技能编译。 |
| [TMEM](https://arxiv.org/html/2606.04536v1) | 代理在单个回合中抽取 QA 式文本监督，再对持久 LoRA 做在线 SGD；固定投影 $A$、累计更新 $B$，并用 RL 优化产生监督的基础策略。报告 CL-Bench 等。 | “参数记忆、累积 LoRA、RL 改进记忆”已有先例。我们的区别候选是**不做测试时梯度更新**、直接从自身原始交互反馈生成参数，并用跨题写入／冻结未来回报训练；这些区别必须实测，最好加入 TMEM 式在线 SGD 对照。 |
| [CLAW](https://arxiv.org/html/2609.12278v2) | 测试时用少量环境交互转移，经超网络一次生成世界模型的 LoRA，并在连续控制环境中在线适应。 | “轨迹转 LoRA、无内循环梯度”也不是首创；我们的目标若成立是 **LLM 代理跨任务行动策略**及自身轨迹的未来效用信用，而非世界模型适应。 |
| [Code2LoRA](https://arxiv.org/abs/2606.06492) | 对代码库差异用循环状态逐次维护适配器。 | “不断更新一个 LoRA”不能作为单独创新点。 |
| [BQ-LoRA](https://arxiv.org/html/2609.12896v1) | 从代理轨迹梯度训练共享 LoRA，用参考决策分布衡量行为等价，平衡并压缩更新；报告 AppWorld、BrowseComp-Plus。 | “矩阵距离不等于行为差异”已有更系统的研究。我们的四结果动作／后续策略干预可成为独立的**未来回报信用方法**，但不能声称首次发现该几何问题。 |

特别注意 [TMEM 的 CL-Bench 实验协议](https://arxiv.org/html/2606.04536v1#S5.SS1)：其主表是经 Qwen3-30A3B 事先筛出的 289 题，用 Qwen3-Max 按 rubric 判断是否正确；论文也在附录报告未筛选集。其 Qwen3-4B 主表总分为 **32.87%**，无记忆为 **30.45%**，但这组数不能直接与本仓库的官方任务执行／评分结果并排比较。要对照，必须在相同题目、演员、内存触发、尝试预算、评分器和计算成本下重新运行；至少明确写出未能复现的部分。

当前最有希望、但尚未证实的论文主张是：**从空历史开始的 LLM 代理完成一题后，直接用自身动作—观察—反馈生成低秩参数经验，并依据对未来任务的因果回报信用决定写入，使持续更新在新题序中带来超越单条固定 LoRA 与公平文本经验的收益。** 这需要同时满足：新轨迹输入内容绑定；写入／冻结配对训练；整道题和整条来源转移留组泛化；冻结官方多题序；各方法自身闭环；等演员、题目、预算、token／GPU 开销的文本与在线 SGD 参数记忆对照。现有 v9、v12、v16 只提供局部机制和训练信号，不能代替最后的性能证明。

以上“区别候选”是对所列论文的**推断性定位**，并非穷尽检索后的新颖性保证。若 v17 门控或后续生成器不能在独立闭环中超过固定首条，论文应收缩为严谨的负结果／信用分配研究，而非声称已经解决在线参数经验学习。
