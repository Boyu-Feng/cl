# 官方 ALFWorld 新题序：同来源原生 MemRL 文本记忆对照

[冻结的 `valid_seen` 36 题计划](alf_fresh_seen36_v6_plan.json)已在读取本轮题目奖励前提交，六类各六题。当前 LoRA 在线比较由同一个无记忆 Qwen3-4B 冻结演员逐题生成轨迹，**只把环境判赢的完整自身轨迹**加入共享来源流；持续 LoRA、固定第一条成功 LoRA、原始历史文本和无记忆臂都在下一题使用同一批可得历史。它能隔离记忆表示与更新的作用，但尚不是各方法分别由自身策略采集历史的闭环比较。

为加入更强的文本经验对照，`evaluate_alf_fresh_seen_memrl_v8.py` 使用仓库已有的原生 MemRL 适配器，而不是把历史直接塞进提示。每题开始前，MemRL 从截至上一题的共享成功来源库检索；同一个冻结 Qwen 演员据此做一次 50 步官方环境尝试。随后仅当**共享无记忆来源轨迹**在本题获胜时，MemRL 读取该公开轨迹、由原生 writer 生成经验、写入本地存储并按官方回报更新所检索经验的 Q 值。未来题目永不进入当前查询。BGE-M3 检索器沿用先前 MemRL 对照，检索后展示给演员的经验限制 2048 token，writer 上限 256 token。原始文本臂也是 2048 token；各臂的演员模型、游戏、50 步、可用命令限制、两轮演员对话和循环保护相同。MemRL 多出写入、嵌入、检索计算，因而这是**同来源、同环境交互预算**对照，不是相同 FLOPs 的系统速度比较。

它的 Q 值更新使用的是共同来源流中无记忆演员的官方结果，不是 MemRL 演员自己刚刚作出的动作回报。这使文本记忆和 LoRA 得到同一批历史，便于比较接口；完整的各方法自行行动、从自身反馈持续学习仍需另跑。基准流完成且原环境审核通过后，已为所有新目标和历史轨迹另建带内容哈希的 ignored 审核文件 `data/annotations/alf_fresh_seen36_memrl_v8_reviewed_20261007.json`；不复用旧历史 ID 作为标签。`audit_alf_fresh_seen_memrl_v8.py` 重放所有目标动作并检查每次检索上下文、成功写入及原生 memory 快照。代码先于本轮最终成绩写定。

上述预定程序现已执行完毕。36 道同题、同来源流的官方 `valid_seen` 成绩为：无记忆 **11/36**，直接放入自身成功历史原始文本 **9/36**，原生 MemRL 文本经验 **13/36**，持续 LoRA **15/36**，固定首条 LoRA **15/36**。MemRL 对持续 LoRA 有 **5 道独有成功**，LoRA 有 **7 道独有成功**；MemRL 对原始文本有 **4 道独有成功**，反向为零。34 题检索到非空经验；11 条共同自身成功轨迹触发 11 次原生 writer 写入，记录的 writer 输入／输出 token 总数分别为 **18093／1962**，单题检索提示最多 **1046 token**。因此这不是把空记忆误当成 MemRL 的对照；但这些额外写入与嵌入计算也意味着不能声称计算预算完全相等。

独立审计检查了每题的官方游戏哈希、只来自因果过去的来源链、原生记忆快照与检索上下文，并将全部 36 条 MemRL 动作轨迹在原 ALFWorld 环境重放，**零失败**。这一个已冻结题序上，参数经验比原生 MemRL 多两题，但样本量和方法各自独有成功均提示差异未稳固；更不能推出参数记忆一般优于文本经验。两法使用共同无记忆演员的成功轨迹作为来源，不代表各方法凭自身策略采集经验的闭环表现；此外 `valid_seen` 题序只相对于指定历史报告档案为新，仍需多独立题序及方法自身闭环复验。
