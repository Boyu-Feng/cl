# CLBench：类型化证据提示与独立原始模型基线（2026-10-09）

## 问题和协议

用户要求证据跨场景使用，但继续保持类型化记录的格式，不能改为任意自由文本总结。本轮区分三种方法：

1. **每题独立原始模型**：固定 Qwen3-4B，不激活 LoRA、不读历史证据、不跨题写记忆；每题按官方独立实例重置。
2. **LoRA 参数记忆**：沿用 `clbench_hyperlora_v2_20261008.pt`，冻结 Qwen 与超网络；只从此前任务的 LoRA 对照轨迹按奖励门控写入因子，下一题检索因子。不是在线 SGD。
3. **LoRA＋类型化证据提示 v23**：与 LoRA 对照读同一参数记忆；从此前 LoRA 对照的公开观察、动作、反馈、官方奖励生成带来源哈希的记录，按当前问题的词重合度选至多三个不同来源，每条保留动作和字段类型、原动作、反馈及哈希。把这些 JSON 记录加入模型当前提示，由模型产生符合当前 schema 的动作。**没有训练或调用证据使用门控，也没有自由文本经验 writer。**

第三组使用共享 LoRA 对照来源，只是同来源的读取对照；不是两套策略分别闭环采集历史。若 LoRA 输出违反当前 schema，冻结底座安全回退与此前运行一致。官方奖励只用于报告和历史选择；扑克及 Cohort 的非 0–1 奖励在 v23 类型化记录中保留原值。

四个本机可运行的官方领域均以 seed 42、index 0 到最后一题冻结目标 `instance_id` 和初始问题哈希：频谱 90、扑克 120、数据库 30、Cohort 20。Cohort 使用 8192 输出 token 和 32768 上下文，其余 512/16384。Sales 与 Codebase 需要 Docker，本机用户没有可连接的 Docker daemon，故不在可运行样本内。频谱早期 20–55 和 56–79 已用于旧门控训练／开发；因此包含全序列的结果是描述性比较，不称为未见盲测。v23 本身不训练门控。

扑克独立原始模型 120/120 已完成并经审计通过，零失败，官方奖励均值 −0.70833。部分牌局由环境直接终止，演员调用数为零且没有响应日志；审计对这类记录同时核验 `actor_calls=0`。

用户进一步指定“先归纳为结构化证据，再推理”后，v23 扑克和 Cohort 运行分别在已记录的 17/120 和 2/20 处停止；前缀工件保留，不将它们写成全域成绩。频谱／数据库 v23 已完成的全量消融仍有效。后续 v24 使用模型生成且按来源校验的固定字段类型化摘要。

频谱独立原始模型、LoRA、v22 类型操作，以及数据库前三组均完成全部目标、没有失败记录且各自审计通过。频谱独立原始模型与 LoRA 逐题奖励 90/90 相同；数据库 30/30 相同。频谱 v22 类型操作 85 胜、5 平、0 负；其门控决策 85 次 `array_union`、1 次弃权。数据库 v22 413 次证据决策全部弃权：30 题来源动作共有 912 个字段值，均为字符串，旧门控只支持数组与数值操作，因此提示候选虽然存在，最终没有改写动作。此处不能把数据库平局解释为无历史证据。

v23 的频谱 90/90 和数据库 30/30 均已审计通过，零运行失败。审计检查冻结目标、来源顺序、记录哈希、选出的来源步骤、提示内容哈希、官方奖励和参数写入顺序。频谱 89 题收到历史提示，最终动作轨迹只在 3 题有别，官方奖励 **0 胜、0 负、90 平**。说明直接给模型类型化记录，未使它执行先前有效的数组合并操作。数据库 29 题收到历史提示，29 题最终轨迹变化，但只有 **1 胜、1 负、28 平**，两处差额各为 0.0667，均分恰好抵消。观察到模型沿用旧题表名查询当前不存在的表、浪费探索次数；证据有格式和来源仍不能自动保证跨实例适用性。数据库 LoRA 对照只写入一次参数记忆，频谱写入 44 次；这两领域的独立原始模型与 LoRA 每题得分仍完全相同。扑克和 Cohort 的完整结果与原因将在运行结束后补充。

## 与 MemRL 的关系

MemRL 把轨迹经 writer 形成可检索经验，先按语义召回，再按逐条经验的 Q 值选择，并用后续奖励更新 Q。v23 存储的是带哈希的具体类型化记录，使用词重合检索，无 writer、无逐条 Q 值，也无训练后的证据使用门控；LoRA 因子记忆同时参与推理。两者对历史反馈的利用层级不同。仓库中的 MemRL 本地移植还包含 BGE-M3 及其协议改动，历史不同运行的绝对分数不能直接归因于机制差异。

历史报告中可供定位的**组内相对基线差值**如下，不能跨行当作同题、同预算的胜负排序。MemRL v21 为种子 303/404 各自的后 80% 在线序列；Reflexion／ExpeL 为两个种子的后 80% 共同可计分测试集，且 Reflexion 可同题重试。当前 v22/v23 为种子 42 的完整顺序，每题一次。

| 方法与协议 | 频谱 | 扑克 | 数据库 | Cohort |
|---|---:|---:|---:|---:|
| 本轮 v22 类型操作 − 同源 LoRA，完整顺序 | +0.05477 | 未完成 | 0 | 未完成 |
| 本轮 v23 类型提示 − 同源 LoRA，完整顺序 | 0 | 运行中 | 0 | 运行中 |
| MemRL v21 结构化投影 − 原生 MemRL，后 80%，303／404 | +0.15788／+0.16151 | +0.10938／+3.07813 | −0.02500／+0.05000 | +0.07525／+0.09000 |
| Reflexion − 无经验，后 80% 两种子 | −0.00013 | −2.27604 | +0.00417 | +0.02011 |
| ExpeL − 无经验，后 80% 两种子 | 0 | −1.51302 | −0.03125 | −0.00115 |

MemRL v21 的主要提升来自其结构化动作投影，不应归因于原生 Q 值检索本身；详情见 `ttcl/memrl_comparison/RESULTS_20261003.md`。Reflexion／ExpeL 的本地移植与取样／重试规则见 `EXPERIMENTS.md` 的“CLBench 最终汇总”。
