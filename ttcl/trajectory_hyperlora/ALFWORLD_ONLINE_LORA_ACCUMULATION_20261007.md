# ALFWorld：从空历史逐题累积 LoRA 参数

本实验回答“能否不再每题重读全部历史，而是把完成任务后生成的 LoRA 直接更新到持久参数状态”。这是**推理时的参数记忆更新规则**：Qwen 演员、超网络和 LoRA 的 `A` 因子全部冻结；每完成一题，超网络只读刚产生的自身轨迹，输出本题的 `B` 因子。下一题只挂载累计 `B`，历史文本仅留作审计，不再进入演员或超网络输入。成功与失败轨迹都按预定协议写入，官方 `won` 决定是否成功。

比较两种不需要训练的新更新规则：直接求和 `B_{t+1}=B_t+\Delta B(\tau_t)`；运行平均 `B_{t+1}=B_t+[\Delta B(\tau_t)-B_t]/(t+1)`。由于所有来源共享冻结的 `A` 因子，`B` 的加法对应实际低秩权重更新的加法。运行平均仍然**逐题原地更新持久参数**，而不是重新编码全部历史；它避免无界增大参数尺度。作为对照，旧在线版每题从截至当时的全部自身轨迹重新生成 `B`，不保存上题的 `B`。

## 第一组：此前使用的 18 道训练域在线顺序

目标来自冻结 ALFWorld `train` 计划的前六个三题序列；同一 Qwen3-4B 和原在线 checkpoint，每题 30 步、每步最多 64 个新 token，贪心可用命令约束。来源从空历史开始，仅上一题已完成的自身轨迹可更新下一题的参数。新运行各自使用重新审核的目标列表、内容哈希及参数状态链；旧版结果作为固定对照，三组沿各自已产生的动作轨迹在线前进。

| 方法 | 官方成功／18 | 最后一题前后 LoRA 因子范数（两层，近似） |
|---|---:|---:|
| 无 LoRA | 6 | 无 |
| 旧版：全部历史重新生成 LoRA | 7 | 未保存累计参数 |
| 每条轨迹的 LoRA 直接求和 | **0** | **256、172** |
| 每条轨迹的 LoRA 运行平均 | **7** | **14.6、9.8** |

两种新更新都跑满 18 题，零环境／模型运行失败，逐题的既往轨迹摘要与参数状态哈希连续。首题从空参数开始，动作轨迹与旧在线版完全相同。运行平均和旧版的 18 题成功集合相同，其中 17 题的完整动作轨迹也相同。直接求和的范数从首题约 14.8、9.9 增至 255.9、171.7；这次负结果说明，不能把未校准的超网络输出直接无限叠加。运行平均表明只保存持久低秩参数、逐题更新，至少在这组顺序上可以达到旧版重读文本历史的效果，但没有提高成功数。

第一组完整审计结果 SHA-256：`d9fb0233923e6f0d4785e70299e973aacf5c8b222221af8ffc2f348e7046cd62`。

## 第二组：新的 18 道训练域在线顺序

使用相同冻结计划的第 7–12 个三题序列，目标文件和顺序重新审核，与第一组 18 题不重叠。仅比较旧版全部历史重算与运行平均参数更新；直接求和已在第一组出现 0/18 与尺度爆炸，不再用于此组。两边从空历史独立执行，并保留无 LoRA 对照。

18/18 道全部完成且零运行失败，逐题内容绑定、既往轨迹和参数状态链审计通过：

| 方法 | 第二组官方成功／18 |
|---|---:|
| 无 LoRA | 2 |
| 旧版：全部历史重新生成 LoRA | **5** |
| 持久 LoRA 运行平均 | **5** |

运行平均与旧版在第二组的 **18/18 道完整动作轨迹完全一致**；最终两层因子范数约为 14.8、9.9。合并两组不同的 18 题训练域顺序，旧版与持久参数版均为 **12/36**，无 LoRA 为 **8/36**；第一组 17/18 道轨迹一致，第二组 18/18 道一致。按本轮“只要性能不下降”的预设目标，**运行平均更新已通过这 36 题的探索性验证**。这支持把历史压进不断更新的低秩参数状态，在测试时不再重读原始轨迹；它尚未证明更广泛任务或 `valid_unseen` 场景上都不下降。

第二组审计结果 SHA-256：`185e321a85f02955ddce711fe18e391e4eb90a31977e26060b488be538b8b524`。本机原始报告和新目标审核在 Git 忽略路径，clone 后不能仅靠这个哈希恢复数据。

## 复现与局限

`alfworld_online_accumulate_lora_v1.py` 准备内容绑定目标、执行 `sum`／`mean` 更新并记录每题历史和 LoRA 因子哈希；`audit_alfworld_online_accumulate_lora_v1.py` 检查目标顺序、旧来源绑定、参数状态链、预算、官方奖励及失败记录。旧 `alfworld_online_from_empty.py` 未修改。模型、数据、轨迹、审核记录和检查点仍位于 Git 忽略路径，只提交代码与结果说明。

这些顺序属于 ALFWorld 官方训练域的**探索性在线评测**，不是刚才 134 道 `valid_unseen` 题的延续，也不能把两组成功数相加冒充官方测试成绩。当前实验没有训练新的“善于累积参数”的超网络；它只比较对现有超网络输出的不同在线组合规则。若跨题更新规则要用于更强的任务条件超网络，还需在该结构下重新训练、评估并处理任务条件与参数累积的交互。
