# ALFWorld 在线参数经验：任务条件、成功门控与独立顺序复核

## 问题与方法

此前的原始超网络在两组各 18 道 ALFWorld 训练域题上，从空历史逐题更新 LoRA `B` 的运行平均，达到与「每题重读全部历史」相同的 **12/36**，高于无 LoRA 的 **8/36**。这说明持久参数状态可以替代那一版的历史重编码，但不能单凭成功数认为两种计算具有不同的经验提取能力。

本轮先在两组旧在线轨迹的**相同历史前缀**上重新计算 `B`：36 个前缀中，逐条轨迹 `B` 的运行平均与全部历史重编码 `B` 的余弦相似度均值 **0.999985**、最小 **0.999936**；相对 L2 差均值 **1.01%**、最大 **2.91%**。因此旧版的 35/36 条动作轨迹相同，很大程度可由因子几乎等价解释；这本身不是一个新的通用在线收益。审计数据 SHA-256：`2e6f2c4a2c44bc8b3e1b9b4df67a1aeb436eb1f5923d2fb1d8af1ade6bdf2f19`。

随后换用已有的、曾在固定专家来源的官方 `valid_unseen` 配对中表现更好的**任务条件上下文超网络**。Qwen3-4B 演员、超网络和 LoRA `A` 全部冻结；每条链从空历史开始，每完成一题才读取自身真实轨迹、环境反馈和官方 `won`。每题单次尝试，最多 50 步、每步 64 token、仅保留 2 轮演员对话历史、约束到环境可用命令，并使用同一个两次重复动作保护。训练域的已审核目标和输入内容哈希固定，三种在线记忆沿各自的真实动作轨迹独立推进。

比较三种更新：

1. **持久 LoRA 因子**：将新轨迹用其初始任务上下文转为 `B`，按运行平均更新持久 `B`；后续题直接挂载 `B`，不再按新题反馈重算。
2. **持久轨迹向量**：每条新轨迹编码一次，按运行平均更新向量；行动时将该向量与当前题反馈送入冻结超网络，实时生成任务条件 `B`。
3. **成功门控向量**：与 2 相同，但只有官方 `won=True` 的自身轨迹能更新向量。失败题仍完整记录在历史和审计中，不进入参数记忆。这个门槛只用公开环境回报，没有专家轨迹或人工类别规则。

每条写入轨迹的编码上限为 2048 token；超过上限时按预设规则保留头尾各半，报告原长度和保留长度。原始轨迹在本机 ignored 结果里完整保留，不把截断的文本冒充完整输入。

## 第一组：此前第二批的 18 道训练域题

| 方法 | 官方成功／18 | 对照说明 |
|---|---:|---|
| 无 LoRA | 6 | 持久因子组逐题配对的同模型演员 |
| 持久 LoRA 因子，所有轨迹更新 | 5 | 18 次更新，因子范数稳定，未出现直接求和的尺度爆炸 |
| 持久轨迹向量，所有轨迹更新 | 5 | 每一步根据当前反馈重算任务条件 `B` |
| 持久轨迹向量，仅成功轨迹更新 | **7** | 7 次更新；与无 LoRA 逐题比较为新增 3 题、退化 2 题 |

三组均完成 18/18、零运行失败。持久因子与所有轨迹向量在 **14/18** 题的完整动作轨迹相同、成功集合完全相同；持久因子与无 LoRA 仅 **1/18** 题轨迹相同，证明参数确实改变了动作，但改动未形成净成功收益。成功门控相对所有轨迹向量多成功 **2 题、少失败 0 题**；这条链与所有轨迹向量在 16/18 题发生动作轨迹分叉。所有轨迹更新时 15/18 条来源超过 2048 token；成功门控实际写入的 7 条来源中，1 条超过该预算。来源筛选与更少截断同时发生，本实验不能将两者贡献分开。

本组逐题目标、轨迹来源、参数状态哈希链、预算和官方回报审计通过。综合审计文件 SHA-256：`7cddb9bbf4fd58ebc8ce338761b1e4c0101e60f6c56c0b801cd5a063b3cb0dcc`。

## 独立顺序复核

同一门控规则、checkpoint 和预算原样用于另一组不重叠的 18 道 ALFWorld 训练域题，即此前原始在线研究用过的第一批题。新运行重新审核了目标内容与方法输入绑定；本组从空历史单独开始，**不是**接在第一组 18 题后面。三臂均完成 18/18，零运行失败，审计通过。

| 方法 | 第二组官方成功／18 | 与无 LoRA 逐题得失 |
|---|---:|---|
| 无 LoRA | 7 | — |
| 持久 LoRA 因子，所有轨迹更新 | **9** | 新增 3、退化 1 |
| 持久轨迹向量，仅成功轨迹更新 | **9** | 新增 3、退化 1 |

两种参数记忆的成功数相同，但各有一题独有成功。门控组 9 次更新，2/9 条写入来源超过 2048 token；全写入持久因子组有 12/18 条来源超过预算。第二组审计文件 SHA-256：`56ff59fa6f690446cd769f6fcad30c9b6d79b3a5b24ed9ebfb5c0c6bc7f116da`。

两组共 **36 道不重复的训练域题**，分别从空历史开始：无 LoRA **13/36**，全轨迹持久因子 **14/36**，成功门控向量 **16/36**。门控在两组都高于无 LoRA，但第二组与持久因子持平；这支持进一步验证门控输入质量，不支持宣称门控已稳定优于其他在线更新。两组都用来探索方法，不能将合计当成独立的官方 `valid_unseen` 检验。

## 解释边界与复现

任务条件超网络此前在固定专家来源的 `valid_unseen` 中有收益，不代表从空历史的自身轨迹也能提供同质量输入。本轮第一组对这个区别给出直接证据：全写入的两种表示都为 5/18，低于无 LoRA 的 6/18；成功门控为 7/18。第二组则显示全写入因子和门控都能达到 9/18，高于无 LoRA 的 7/18。题序、来源质量和截断频率都可能影响收益。这里的 36 题均属于 ALFWorld 官方**训练域**，也不是 MemRL 的等预算完整在线对照。尚不能声称任何一版在官方 `valid_unseen` 或 CLBench 上稳定有效。

实现和复核入口：`analyze_online_lora_factor_equivalence_v1.py`、`alfworld_online_persistent_context_lora_v1.py`、`alfworld_online_context_vector_mean_v1.py`、`alfworld_online_context_vector_reward_gate_v2.py`、`audit_alfworld_online_context_memory_v1.py`、`audit_alfworld_online_reward_gate_replication_v2.py`。模型、数据、审核记录和原始结果仍在 Git 忽略路径；Git 只保存代码与本文汇总。下一步应在冻结的官方 `valid_unseen` 顺序上检验这个固定更新规则，并针对自身成功／失败轨迹的不同质量训练超网络，同时控制长轨迹中段信息丢失。
