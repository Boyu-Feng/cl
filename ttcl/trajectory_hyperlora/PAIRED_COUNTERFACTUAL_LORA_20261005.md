# 同题换历史的轨迹→LoRA 配对试验（2026-10-05）

## 要检验的问题

旧的直接轨迹→LoRA 试验在训练规则组合上可拟合，在未见三标记组合上不稳定。本轮固定下一题，只把已完成历史换成**观察、反馈、数字和模板均相同，但每步动作相反**的轨迹，检验超网络生成的 LoRA 是否令输出动作按来源正确翻转。该合成环境仍非 ALFWorld／CLBench；动作 `LEFT`／`RIGHT` 的正确性由预先固定的环境规则判定。

训练组合是 `0,1,3,4,6,7`，完整规则 `2,5` 留出；Qwen3-4B 底座和原有轨迹编码器冻结，只从先前分阶段训练的种子 42／43 checkpoint 继续更新 LoRA 因子生成头。每步选一个训练组合和一个标记，在**同一道下一题**上计算正确来源与相反来源的动作交叉熵，并要求正确动作在正确来源下的对数概率高于错来源。训练来源每步重新采样，查询读数不在来源中。300 步，学习率 `0.0003`，两个种子预先固定。

评估使用训练中未见的来源随机种子 `3001,3002`、新查询措辞及新读数 `151,152,163,164`。每个分割为两种完整规则 × 两条来源 × 三个标记 × 四个读数，共 48 个配对判断。四臂都面对**同一道题**：无 LoRA、六种训练规则来源生成 LoRA 的公共平均、正确来源、相反来源。严格判定第一个动作 token，保存每条来源与查询的 SHA-256、输出 token 和动作对数概率；不能将此数值与旧的完整生成首词判分直接并表。

种子 42 在留出组合上从 30/48 到 32/48，种子 43 完全没有提升。更关键的是，种子 42 已见组合的正确来源只有 16/48、错误来源却 32/48；因此“输出随历史变化”不等于“正确使用历史”。种子 42 留出组合的首动作会在同题换历史时全部翻转，但仍有整个 `BETA` 标记的两种规则全部答错。种子 43 的配对训练把已见组合提高到 40/48，留出组合仍只有 16/48，主要在 `ALPHA` 与 `GAMMA` 出错。生成头学到了部分训练组合的对比，却没有稳定组合泛化。

进一步把已预训练的三位关系预测硬离散化，再线性映射到 LoRA 因子，做相同配对训练。种子 42 的已见／留出正确来源为 22/48、26/48；种子 43 为 38/48、16/48。这个显式瓶颈没有解决问题。旧的关系预测也非完美，且 LoRA 对多个标记的作用经冻结模型非线性耦合；单纯提高来源对比权重或继续延长相同训练，没有充分依据。

首次草测曾在训练与评估共用查询措辞，且相反来源的其他内容未完全对齐；其输出保留在本机，但**不计入上表证据**。上表来自修正后的独立措辞、逐步同观察／反馈配对版本。由于研究过程中已反复查看同一留出规则，仍是探索性诊断，不是独立确认集。没有使用环境终局 RL 奖励，也没有运行 ALFWorld／CLBench 评估。

## 下一步判断

当前瓶颈主要在把已识别的多条条件关系**组合写入同一个 LoRA**，而非只在于是否检索或是否注意来源。下一次应固定一个新的、预先不查看的规则组合划分，先在训练规则上检查每个标记的来源翻转方向，再测试未见组合。实现上可将每个关系槽映射为相互约束的 LoRA 子空间，减少标记间干扰；同时保留整段轨迹编码器的可学习性，并用同题正确／错来源和无来源三臂的配对收益训练。只有正确来源稳定胜过公共及错来源，才值得移到 ALFWorld 奖励训练。

代码入口为 `paired_counterfactual_lora.py`。原始逐题记录与小 checkpoint 在 ignored 的 `results/trajectory_hyperlora/paired_counterfactual_20261005/`，不上传 Git。训练仅使用空闲的 GPU 3，单进程显存上限 35%；没有停止或修改其他卡上的实验。
