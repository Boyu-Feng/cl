# 通用轨迹→LoRA 奖励训练：算法接口与首轮诊断（2026-10-07）

目标是让一个共享超网络从已完成轨迹中生成参数经验，并靠**后续独立任务的环境收益**训练；不预先定义 XLand 规则、ALFWorld 任务家族或固定动作编号。训练后的超网络冻结；在线阶段从空历史开始，完成轨迹后生成新的 LoRA，用于后续任务。底座演员也冻结。

## 方法

来源轨迹是环境公开可见事件的序列。通用序列化保留每条事件的原始字段和值，不作规则总结。编码器与生成头将文本映射成目标演员的 LoRA 参数：

\[
 z=E_\phi(\tau),\quad \Delta W_\ell= B_{\phi,\ell}(z)A_{\ell},\quad
 \pi_{\phi,\tau}(a\mid h)=\pi_{\theta+\Delta W(\tau)}(a\mid h).
\]

现有 `general_relation_hyperlora.py` 已有不按规则命名槽位的轨迹编码与 LoRA 生成模块，但原训练主要是后续正确动作的交叉熵。新训练核心 `trajectory_lora_rl.py` 则对**后续目标**在同一环境重置和预算下分别运行无 LoRA 与来源 LoRA，记录真实终局奖励。LoRA 分支按当时策略采样动作，之后对实际采样动作重算联合对数概率，更新超网络：

\[
 \widehat{\nabla_\phi J}=(R_{\rm LoRA}-R_{\rm base})
 \nabla_\phi\sum_t\log\pi_{\phi,\tau}(a_t\mid h_t).
\]

基线与 LoRA 使用相同环境重置种子、不同动作采样流；否则初始化时两个策略相同会逐步采到完全相同的动作，优势恒为零。梯度只通过实际采样动作的概率回到超网络，不把失败轨迹中的所有动作判成坏动作，也不需要环境可微。训练目标可以有不同动作空间和奖励函数；环境适配器负责动作采样、可行动作约束、原生奖励及预算，演员适配器负责在同一策略下重算动作概率。必须保证重算概率与实际采样策略一致，包括温度、动作约束和停止动作。通用核心强制训练划分、目标内容哈希、同一目标重置、完整回合及预算检查；失败回合要保留在外部记录，不能静默用于更新。

## 当前验证与边界

两动作小型机制测试把不同来源轨迹映射为相反策略，原策略两个动作均为 0.5。300 次配对环境奖励更新后，红色来源选择动作 1 的概率为 **0.0110**，蓝色来源为 **0.9854**；单元测试同时检查测试集目标不能进入训练。它只验证通用奖励梯度和来源条件化能运行，**不是** XLand、ALFWorld 或 CLBench 成绩，也没有验证大模型 LoRA 生成器在真实环境的收敛。

另将 v9 官方 XLand 超网络继续训练为读取“尚未获得正奖励”的来源前缀，得到 v10。冻结 trivial 专家动作仍为 **56/130**，与 v9 相同；无正奖励前缀测试从原 **55/130** 变为 **54/130**。在与 v9 相同的 8 个新规则集、从空历史在线交互的官方环境配对中，v10 无 LoRA／全部历史 LoRA／正奖励门控为 **0/8、1/8、0/8**，v9 也是 **0/8、1/8、0/8**。v10 全部历史分支的原生总回报 0.9593，高于 v9 的 0.4519，但只有一个成功规则集，且冻结动作指标没有提升，不能据此宣称更好。v10 结果通过官方环境奖励审计，8 条完成、0 条失败。这个 XLand 专用预处理是输入差异诊断，不作为通用方法的核心。

目前尚缺真实环境适配器把新通用梯度核心接到 Qwen 的轨迹生成 LoRA 上，也缺跨 ALFWorld／XLand 的正式训练与独立测试。因此目前可以说**训练方法已具体实现并通过机制验证**，不能说“通用效果已验证”。下一步应先接 ALFWorld：沿用已审核 train 来源／目标绑定，以同一游戏重置、官方通关奖励和相同 30 步／64 token 预算采样，并实现带可行动作约束的概率重算。再接官方 XLand 多步任务，保持相同训练核心，只更换环境适配器；各自用独立未见任务比较无 LoRA、文本轨迹和生成 LoRA。训练轨迹的新目标须另行审核并绑定输入内容，不能沿用旧 ID 的标签。
