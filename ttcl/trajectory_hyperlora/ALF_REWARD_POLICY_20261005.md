# ALFWorld 环境奖励训练轨迹条件 LoRA 策略：结果与下一步

## 结论

这轮确实用 **ALFWorld 真实终局获胜奖励**训练并测试了一个轨迹条件参数策略，但更新范围是选择 `base`、公共 LoRA、来源 LoRA 的轻量策略头；**原始轨迹编码器和 LoRA 因子生成器没有接受 RL 更新**。新选的 36 道 `valid_seen` 游戏中，冻结策略成功 **8/36**，基模和公共 LoRA 均 **7/36**，有训练来源的 30 题上来源 LoRA **7/30**。策略相对基模有 2 题独有成功、1 题独有失败，净差 +1；这是很弱的探索性信号，不能称为稳健提升，更不能称为从特定轨迹学出了可迁移的参数经验。

更有判别力的内部结果是：把来源换成同家族另一条已审核训练轨迹，30 题里 **27 题的策略选择会变**，说明策略确实读取来源 latent；但正确来源 LoRA 与公共 LoRA 在这 30 道测试游戏的**终局奖励完全相同**，仅 6 道游戏的命令轨迹不同。当前策略学会了根据来源改变配置，却没有证据表明这种改变抽取了有用的来源特异经验。

## 为什么做这轮

这条想法来自几层逐步收紧的问题。早期 MemRL／文本经验实验提示：写出合理文字不等于下一题能在正确阶段使用它，且终局成败很难归到某条经验或某一步。于是改问：能否从轨迹生成可挂载的**参数经验**，让后续任务的损益直接决定哪些信息值得写入。受控奇偶规则实验给出可行性下界：逐规则训练的小 LoRA 在未见读数上两种子均由基模 4/8 提升到 7/8，错规则 LoRA 仅 1/8；这只证明 LoRA 能承载简单抽象规则，**不是**证明超网络会从新轨迹即时生成它。

接着直接训练轨迹→LoRA 超网络，未见规则组合的表现随种子大幅波动，错误轨迹有时反而更好；这指出轨迹编码和规则组合泛化仍有缺口。到了 ALFWorld，之前的监督式轨迹→LoRA 主要产生跨来源公共更新：训练来源生成的有效 LoRA 更新平均余弦约 0.989；不同家族错误来源仍能保留多数获胜案例。中心化残差训练虽把正确与错误来源的训练损失拉开，开发动作输出仍相同。因而这轮先检验“下一题真实环境奖励能否教会模型什么时候用哪种参数”。它是直接环境奖励驱动的最小 RL／上下文 bandit 实验，不替代未来对 LoRA 生成头本身做奖励训练。

## 协议与训练

使用冻结 ALFWorld 计划中的 51 道已审核训练游戏：31 道来自成功轨迹动作审核目标，20 道来自另行审核的无动作标签奖励目标。每题有一条**不同游戏、同任务家族、已审核成功的训练来源轨迹**；来源与目标 episode、目标游戏和输入内容均以 SHA-256 绑定。实际从重置环境分别执行三臂，使用同一冻结 Qwen3-4B、贪心和可用命令约束，预算 **30 步、每步最多 64 token**，只从环境 `won` 取奖励。三臂成功数：基模 **24/51**，22 条训练来源的公共平均 LoRA **28/51**，目标对应来源 LoRA **29/51**；只有 7 道题出现任意两臂终局奖励差。所有回合完整，无基础设施失败；原始轨迹留在 ignored 结果目录。

训练策略为 $\pi_\psi(a\mid z_s,g)$，其中 $z_s$ 是旧超网络对来源轨迹的冻结编码，经仅用训练来源拟合的 4 维 PCA 投影；$g$ 从 actor 实际可见的初始任务句子识别任务家族。动作 $a\in\{\text{base},\text{mean},\text{source}\}$ 决定本题挂载的 LoRA 配置。51 题按固定哈希再分为 43 道奖励训练、8 道内部留出。对每道训练题已经取得三个真实环境奖励，因此使用完整反事实反馈，精确计算上下文 bandit 的期望奖励梯度：

\[
\max_\psi\;\frac{1}{43}\sum_i\sum_a\pi_\psi(a\mid z_{s_i},g_i)
\bigl[R_i(a)-\overline R_i\bigr]
+\lambda_H H(\pi_\psi)-\lambda_2\lVert\psi\rVert^2.
\]

这避免仅抽一臂时终局奖励的高方差，但也意味着本轮**只更新选择头**，不是 PPO，也未对新生成的 LoRA 因子反向传播环境奖励。训练固定 200 步、种子 42，内部留出只用于诊断，不选择 checkpoint。训练 43 题中，基模 22、公共 24、来源 25、策略 25；内部留出 8 题中，基模 2、公共和来源各 4、策略 3。内部留出已提示策略会犯选择错误。

## 冻结测试

测试游戏从此前未用于这条分支的 ALFWorld `valid_seen` 中按固定哈希**每个家族取 6 道**，总共 36 道；与原计划训练和 `valid_unseen` 游戏互斥。新建审核文件逐项绑定目标游戏、actor 初始任务句子和审核过的训练来源。清洁家族没有已审核同家族来源，策略只在基模与公共 LoRA 中选择，该家族不计入来源 LoRA 的 30 题。所有 36 道的策略选择及概率在读取任何测试奖励前冻结，两个测试进程的预测 SHA-256 相同；三臂使用相同 30 步／64 token 环境预算。两段结果合并后核对 36 个唯一目标、内容绑定、初始观察和所有可用臂的完整状态。

| 任务家族（各 6 题） | 基模 | 公共 LoRA | 来源 LoRA | 奖励策略 |
| --- | ---: | ---: | ---: | ---: |
| 照明查找 | 4 | 4 | 4 | 4 |
| 普通放置 | 2 | 1 | 1 | 2 |
| 清洁放置 | 0 | 0 | 无审核来源 | 0 |
| 冷却放置 | 0 | 0 | 0 | 0 |
| 加热放置 | 0 | 0 | 0 | 0 |
| 双物体放置 | 1 | 2 | 2 | 2 |
| **全部** | **7/36** | **7/36** | **7/30** | **8/36** |

策略相对基模 2 题独有成功、1 题独有失败；配对差只来自三道双物体任务。在另一道 Mug→Dresser 普通放置题，基模获胜而两个 LoRA 失败，策略预先选择基模，正确避免了一次负迁移。双物体 CreditCard→Dresser 则反过来：基模成功，策略选择来源 LoRA 后失败。CD→Drawer 与 SoapBar→GarbageCan 是策略选择 LoRA 后成功、基模失败，但**公共 LoRA 同样成功**。因此总分中的任何正例都没有证明“特定来源 LoRA 比公共 LoRA 更好”。2 对 1 的配对胜负样本太小，不能认定稳定增益。

来源 LoRA 和公共 LoRA 在 30 道有来源的测试题上终局奖励 **0 道不同**，尽管 6 道题的命令轨迹不同。另做**不运行环境、只读策略输出**的同家族来源替换诊断：30 道中 27 道的配置选择改变，三臂概率平均总变差 0.221。它证明潜变量参与了选择计算，也暴露策略对来源敏感；由于没有替换来源后的环境奖励，不能把选择变化算作成功迁移。

所有测试都是使用官方 ALFWorld 环境 `won` 的内部配对实验；本轮 36 题是新抽样的 `valid_seen` 子集，actor 的贪心约束协议与 LatentSkill 或旧 Delta-Mem 的发表／历史协议不同，分数不能直接横向比较。此前 `valid_unseen` 上的公共 LoRA 10/36 与本轮 `valid_seen` 的 7/36 来自不同任务集合，也不构成重复验证。没有进行 CLBench 测试。

## 与 LatentSkill 的关系、下一条路线

[LatentSkill 原文](https://arxiv.org/html/2606.06087)在推理时可以用已训练的编译器把**现成技能文本**即时生成 LoRA，随后缓存并挂载；编译器主要通过文档预训练及“技能文本＋教师轨迹”的监督学习获得能力，并假设选到正确技能。我们的目标更难：直接从新完成的原始轨迹自动发现可迁移技能，并让后续任务的奖励教会轨迹→LoRA 映射。文本经验可以做**训练期辅助目标或可解释对照**，不必成为推理时必经的文本瓶颈。

下一步不宜把这 51 题稀疏奖励直接用于高维 LoRA 生成头的随机策略梯度。先造出有**来源因果区分度**的任务配对：相似目标在不同历史规律下必须采取不同动作；正确来源、错来源、无来源、公共 LoRA 的环境奖励能清楚分开。以已成功的逐规则训练 LoRA 作为上界，训练轨迹编码器恢复动作—反馈关系，再用下一题正确减错来源／无来源的配对奖励训练低维、受约束的 LoRA 残差；只有在多个随机种子和未见规则组合上通过错来源对照，才增加自由度并转入 ALFWorld。ALFWorld 训练可从阶段性进展取得更密信号，但最终仍以环境 `won` 和新游戏分割评测。若在 ALFWorld 上仍只有公共 LoRA 有效，应报告为通用策略迁移，而非轨迹经验学习。
