# 扩大自身轨迹 LoRA 写入效用训练池：预先冻结协议

旧[108 组配对](ALF_INCREMENTAL_UPDATE_RESULTS_V9_20261007.md)只有 16 组终局胜负不同，低维写入门控没有超过无条件写入。为检验是否只是效用训练样本不足，在读取新回报前，从官方 ALFWorld `train` 游戏中冻结 60 道训练题和 18 道开发题，六种任务家族各 10／3 道。每题与六次已审核的**自身成功轨迹顺序转移**配对，分别比较保持旧 LoRA 与纳入新轨迹后两来源等权均值的 LoRA，共 468 组、936 个计划回合。演员、Qwen、超网络和 v5 残差修正均冻结；每回合 50 步、两轮动作历史、同一限制动作协议，目标题标签只供事后统计，不输入演员或更新器。

题单在结果目录、标注目录和历史结果目录的本地 JSON 中扫描已出现过的官方 `train` 游戏路径（1,969 个）。候选清单 v13 发现有些新游戏与旧记录共享任务目录，**未运行**；保留该清单并另建 v14。v14 从 3,553 个官方训练游戏中按固定哈希排序，每个入选游戏来自不同任务目录。18 道开发题的任务目录完全未出现在扫描快照；60 道训练题中 55 道也满足此条件，另 5 道是从旧记录出现过的目录选出的不同游戏。这里的“新”只相对于本机可扫描的 JSON 历史，不排除未保留记录的外部曝光。开发题不用于训练或按结果反复改选择规则。

每个来源记录、目标题文件、检查点、残差模型及 468 个输入配对均有内容哈希绑定。三个分片按 `target_id % 3` 划分，分别是 156 组，其中训练 120、开发 36；同一目标题的六组转移不会分到不同 GPU。仅在确认空闲的 GPU 0、1、3 上运行，不改动其他卡上的实验。原始轨迹、标注和模型继续留在 Git 忽略路径。冻结题单 SHA-256：`a7f15db7f6bc4d26218427816fbd872fc99f165a0d811cfc5ea17f09800926cc`；被拒绝的 v13 候选清单：`08f68c0d594297538498f3735c44d2fb84e2e13dccd7df40f863fcaa50311224`。

采集入口为 `freeze_alf_incremental_pool_v13.py`、`freeze_alf_incremental_pool_v14.py` 与 `collect_alf_incremental_v14.py --shard {0,1,2} --device cuda:{0,1,3}`。分片输出必须逐条用原环境独立重放；训练门控只能用训练题效用，开发题只在冻结训练方案后选模型。随后仍须在官方 `valid_seen`／`valid_unseen` 多题序、方法自身闭环在线采集、固定首条 LoRA、无 LoRA、原始文本与原生 MemRL 对照中验证。该题池只提供训练和模型选择材料，不能充当论文最终测试集。
