# ALFWorld：把自身失败修正持续存入参数状态

## 更新规则

沿用旧版冻结 Qwen3-4B 演员、旧任务条件轨迹超网络、每题已审核的训练域专家成功来源、共享 LoRA `A`、合法动作约束和同观察同动作两次重复保护。两条方法链各从空失败记忆 `R` 开始，在同一批已曝光的官方 `train` 开发题 24 题上按原顺序、每题单次尝试，分别收集**自己的**回合。最多 50 步、每步 64 token、两轮演员历史。专家来源用于旧版动态 LoRA 和差值参照；更新后的记忆来自本方法自己的失败轨迹。

每题行动时，冻结超网络仍用本题专家来源和当前观察逐步生成 `B_dynamic`；把持久修正 `R` 以本题专家初始有效 LoRA 范数的 25% 为上限读出，实际使用 `B_dynamic + clip(R)`。完成后若自身成功则保持 `R`；若自身失败，则同一冻结超网络从该失败轨迹生成 `B_failed`，从本题专家来源生成 `B_expert`，按旧 v31b/v32 选定的方向计算 `δ = −clip(B_failed − B_expert)`。写入和读取均以实际有效 LoRA 矩阵 `B A/r` 的 Frobenius 范数限幅，不能把这个界解释成策略行为界。

- `failure_mean`：按失败写入次数对所有自身失败修正 `δ` 做运行平均，存一组持久 `R`。
- `failure_latest`：每次失败只保留最新 `δ`，作为“是否真需要累计”的对照。

旧版首次回合按同题单次尝试作对照。三组动作协议和演员相同；在线两臂拥有各自的失败历史，不能把最终差值当成固定来源下单一步更新的纯因果效应。旧超网络、LoRA `A` 和演员都**没有训练**；这里的“学习”是依照自身失败把一组可复用的参数状态写入下一题。

## 训练域先导结果

| 方法 | 官方单次成功 | 自身失败写入 | 运行失败 |
|---|---:|---:|---:|
| 旧版，无持久失败修正 | 11/24 | 0 | 0 |
| 持久修正运行平均 | **13/24** | 11 | 0 |
| 仅保留最新失败修正 | 10/24 | 14 | 0 |

相对旧版，运行平均在题 5、22 独有成功，没有独有失败；只留最新在题 5 独有成功，在题 17、23 独有失败。两条在线链的参数状态在 24 个题后位置中有 20 个不同，终局在 3 题不同；因为回合分叉，两条链的失败写入次数也不同。最新修正臂的读取在 9 题触发 25% 限幅，平均臂为 0 题，所以“平均比最新好 3 题”也混合了状态幅度和历史分叉，不能单独归因为保留多条失败的语义内容。

24 个输入分别绑定官方游戏内容、专家来源记录、旧首次回合、冻结检查点、运行代码和目标哈希；新标注没有依据旧历史 ID 复用标签。独立审计对两臂 **48 条**新回合在原环境逐动作重放，重算每题专家因子、自身失败因子、限幅残差、读出限幅和前后持久状态哈希，全部通过；审计记录 `positions_with_different_state=20`，运行失败 0。

这是**一条已曝光训练域开发顺序**的小样本正信号，不是官方 `valid_*` 独立成绩，也不足以声称失败经验可稳定跨题泛化。旧版每题仍提供专家成功来源，所以它不是“仅从失败轨迹独立学会任务”；平均修正公式不是从未来回报训练出来的最优更新器。下一步需要在训练域做多顺序与来源扰动，再固定规则到未用于选法的新题序；并和只写成功、固定首条失败修正及同预算文本失败经验比较。
