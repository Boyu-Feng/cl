# ALFWorld 方法自身闭环：原生 MemRL 成功轨迹对照

[v19 在线对照](ALF_ONPOLICY_V19_PROTOCOL_20261008.md)已有无记忆、连续 LoRA、固定首条 LoRA 和原始文本四臂，但原始文本不能代表具有经验提炼和检索的文本记忆。v20 新增**独立从空库开始**的 MemRL 臂，沿用仓库先前验证过的原生 writer、BGE-M3 检索、Q 值更新服务以及同一冻结 Qwen3-4B 演员，不手写任务动作或经验规则。

题目严格复用 v19 已冻结的三条互不重叠、每条 30 题的官方 `valid_unseen` 顺序，并在运行前新建内容绑定标注。v20 标注把 v19 对应题目的父绑定、官方游戏文件哈希、演员检查点、MemRL 实现、检索／writer 配置和预算重新绑定；SHA-256 为 `1480dfac46ed9de0faae1ad104dfd8f902a144b0790b698c72c6fa38f3e6e78d`，留在 Git 忽略的 `data/annotations/`。每题运行记录另绑定截至当前题的**自身成功轨迹哈希链**和上次 MemRL 存储快照哈希，不能复用 v19 其他方法的历史。90 道游戏都曾在旧报告出现，因此仍是预定顺序的探索性官方评测，不是新游戏盲测。

每条顺序单独建立空 MemRL 存储。当前题先用初始观察检索，最多 2048 token 的检索文本放入相同演员的提示，执行一次 50 步／每步 64 token／两轮动作历史／两次重复抑制的官方回合。只在**本方法自己的回合**得到官方 `won` 后，才把完整动作与环境反馈交给原生 writer（上限 256 token），并更新已检索经验的 Q 值；失败回合保留原始失败记录但不写入，也不触发 Q 更新。这和 v19 LoRA 的“只有自身成功可进入跨题记忆”准入规则一致，同时意味着本轮并非 MemRL 使用失败信号的最强设置。检索阈值 0.5、种子 42、BGE-M3 embedding 与原生配置沿用旧同来源 MemRL 实验，不能看结果再调。

`evaluate_alf_onpolicy_memrl_v20.py --order {0,1,2}` 生成完整轨迹、检索上下文、writer 计数、输入哈希和每题后的持久存储快照；`audit_alf_onpolicy_memrl_v20.py` 必须在原环境逐动作重放全部 90 条回合，并核对检索文本的 token 数与提示哈希、成功来源记录、writer 输入绑定、Q／存储快照因果链和每个文件哈希。原始轨迹、BGE 权重和存储结果留在 Git 忽略路径。三份 v14 GPU 作业完成且目标显卡空闲前不运行 v20，不改动其他用户的实验。

`analyze_alf_onpolicy_memrl_v20.py` 只有在 v19 十二臂和本轮三臂全部经过原环境审计、原始文件哈希不变时才生成比较。它逐题与 v19 在相同目标上的 LoRA、原始文本、固定首条和无记忆配对，报告三个顺序各自的官方通关数、MemRL 独赢／LoRA 独赢、检索命中、writer 调用与输入／输出 token、演员提示 token 上界代理和环境回合预算。三条顺序才是主要重复单位；不能把 90 题当作 90 个独立在线学习链，也不能把一次 LoRA 与 MemRL 的数值差解释为参数形式的普遍优势。若要主张优于文本经验，还需把强文本总结、失败反馈版本和训练／推理成本纳入独立确认。
