# 在 68/134 旧超网络与动作限制版上读取失败轨迹

## 方法与预算

保留旧版 Qwen 演员、训练域成功专家来源、冻结超网络、逐步目标反馈生成的 LoRA、合法命令约束，以及同观察同动作两次重复抑制。旧版每题的**第一次尝试不变**；本轮只研究首次失败后的第二次尝试。首次成功即停止。旧版 134 道官方 `valid_unseen` 题单次为 **68/134**，同轮带动作限制的无 LoRA 为 **41/134**；那些 134 道题早已曝光，不用来选择本轮更新方向。

开发输入为此前已审核的官方 `train` 分区 24 道开发题，旧超网络和动作限制的首次成功 **11/24**，另外 13 题有完整失败轨迹。重新绑定游戏、专家来源、首次轨迹、冻结检查点与新代码哈希；不依据旧历史 ID 沿用标签。失败后把原始观察—动作—反馈序列交给同一个冻结超网络，得到 `B_failed`；同题专家来源在初始目标上的读出为 `B_expert`。第二次尝试继续逐步使用旧专家来源生成 LoRA，只在每步生成后叠加限幅残差。残差方向与长度在看到重试回报前固定：

| 重试臂 | 第二次尝试的参数处理 |
|---|---|
| `static_retry` | 原旧版 LoRA 原样再试一次，保留重复动作限制 |
| `toward_failure` | 加入 `+clip(B_failed−B_expert)` |
| `away_from_failure` | 加入 `−clip(B_failed−B_expert)` |

`clip` 按实际有效矩阵 `B A/r` 的 Frobenius 范数约束：整组残差不得超过初始专家 LoRA 有效范数的 25%。三个重试臂预算相同，每题最多 50 步、每步最多 64 个新 token、两轮演员历史和相同动作限制。两个方向都只是开发性候选；单次终局失败无法确定正确符号。旧超网络和演员权重始终冻结，这里学习的是重试时使用的 LoRA 参数状态，不是重新训练超网络。

## 运行、结果与限制

24 道开发题、13 道首次失败题均完成，零运行失败。官方成功数为：

| 相同开发题，每题最多两次；首次成功即停止 | 成功题数 |
|---|---:|
| 旧版 LoRA＋动作限制首次尝试 | 11/24 |
| 原样再试一次 | 11/24 |
| 朝失败轨迹因子方向更新后重试 | 11/24 |
| 远离失败轨迹因子方向更新后重试 | **13/24** |

原样重试的 13 条轨迹均逐字段等于旧版首次失败轨迹；在确定性旧演员下，额外尝试本身没有救回题目。远离方向在两道不同任务类型的首次失败题上独有成功，另 11 道失败题仍未成功。两道成功来自普通放置和冷却后放置。朝失败方向没有救回题目。**13/24 是最多两次尝试的开发分数，不能与旧版 68/134 的单次通关率直接相减。**首次与全部 39 条重试回合原环境重放、游戏及来源绑定、官方奖励和预算审计通过。单个确定性随机方向、但按实际有效 LoRA 矩阵范数逐题匹配的对照，13 条失败题救回 **0/13**；其 13 条环境回合独立重放审计也通过。真实失败方向的 **2/13** 是弱开发信号，并不能凭与一次随机方向的差值证明稳定的轨迹内容专属效用。

技术失败记录：v31 首次运行只完成 2 个首次成功输入，在第 3 个输入、生成第一条失败残差时，范数代码访问了清除来源后为 `None` 的临时 `B`。这发生在任何失败重试前，不计为任务失败。原始部分结果和审核绑定保留；v31b 改按冻结层形状校验，新增回归测试覆盖清空 `B` 的情况，重新生成输入绑定后从头运行。

若开发集没有超出等预算原版重试的回报，不把额外尝试后的总成功数写成对原 **68/134 单次** 的提升。开发集和旧 134 题均已在先前研究中用过，不能用于独立泛化结论。结果文件与新审核数据位于 Git 忽略目录；代码实现为 `alfworld_failure_retry_residual_v31b.py` 和 `evaluate_alfworld_failure_retry_v31b.py`，独立重放见 `audit_alfworld_failure_retry_v31b.py`。
