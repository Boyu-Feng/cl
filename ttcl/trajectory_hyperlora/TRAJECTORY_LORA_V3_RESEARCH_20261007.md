# 轨迹超网络 v3：部分历史训练与文本经验对照（2026-10-07）

## 研究问题与版本边界

这轮检验两件事：怎样让**推理时由已观察轨迹生成 LoRA**更早、更稳定地影响后续动作；以及这种接口相对文本经验有什么可验证的收益。先前 ALFWorld 奖励训练版与受控 XLand 两个种子的原始权重均保持不变，另在 ignored `results/trajectory_hyperlora/frozen_baseline_20261007/` 做只读本地副本。新探索策略、部分历史训练器、检查点和结果均使用新文件名。三份原版权重的 SHA-256 分别为 ALFWorld `262060989529f5b6603ec11fed36159dd93a78464df945ec9e34ef025a9b034b`、XLand 种子 42 `31ff888f62d5f00a098a028d9df107d07a02fee199b89d3a70649591acdfe835`、种子 43 `0bbfb5daf30b1c17c14055e8c7715ea34baaa15270f6360aeaf479d9ecb234b3`。本地副本与原文件逐字节哈希相同；权重不上传 Git。

已有工作提供方法背景，但不能代替本仓库的对照：[LatentSkill](https://arxiv.org/abs/2606.06087)将**文本技能**变成 LoRA 并比较上下文技能；[SHINE](https://arxiv.org/abs/2602.06358)与 [Doc-to-LoRA](https://arxiv.org/abs/2602.15902)研究一次生成参数、以后不重复读取长上下文；[MemRL](https://arxiv.org/abs/2601.03192)在文本记忆上学习检索效用。这里直接把**环境轨迹**输入超网络，目标是后续动作和环境反馈，因此不声称复现上述任一论文。

## 受控 XLand：修复“只会读满三条历史”

原顺序不变超网络只用每个来源三个单步试验的完整历史训练。旧[从空历史在线报告](X_LAND_ONLINE_FROM_EMPTY_20261005.md)中，种子 42 三次后 **80/90**，模型平均只试过 1.79 种不同动作；这把**采样重复**与**不擅长读部分历史**混在一起。新 v2 只改来源探索策略：在同一公开状态的离散可选动作中，下一次试验屏蔽已经试过的动作；其余由冻结 Qwen 的动作分数选择。它不知道隐藏机制、正确动作或未选择动作的转移。旧检查点加 v2 采样三次后，种子 42 **90/90**、种子 43 **87/90**；种子 43 比旧在线策略的 **88/90** 少一题。这是**采样策略**的效果，不是新超网络权重。

v3 才更新超网络。新 `xland_prefix_hyperlora_v3.py` 从旧检查点出发，对原 XLand 训练组的三条独立试验取非空子集，重新由真实转移审核目标并为**每个新前缀**计算输入内容哈希。只用 train 组中的两条和三条来源子集训练；Qwen3-4B 保持冻结，以后续动作交叉熵、配对间隔损失及旧权重锚定损失更新轨迹编码器和 LoRA 生成头。开发组选择 100/200/300 步中的检查点，留出测试只在训练与选点结束后评估。训练时没有把机制名、目标动作、未试过动作的转移或测试标签放进超网络输入。两个种子的开发集选点分别是第 200／100 步，完整三条来源均 **147/147**；两条来源子集为 **338/441／339/441**。开发数字仅用于选点，不算留出成绩。

|---|---:|---:|
| 原超网络＋原模型自选试验 | 30／59／60／80（各以 90 为分母） | 30／60／89／88 |
| **原超网络＋v2 不重复探索** | **30／59／57／90** | **30／60／89／87** |

为拆开“探索换了动作”和“新参数读历史更好”，`xland_online_replay_v3.py`把 v2 原检查点实际选择的动作及其经过审核的环境转移**原样重放**给 v3。在完全相同的两条来源轨迹后，种子 42 的旧／新检查点是 **57/90→85/90**：新版本独有正确 28 个实例、旧版本独有正确 0 个；按独立组计，30 组中 24 组提升、0 组退化。种子 43 为 **89/90→90/90**。三条来源后固定历史是种子 42 的 **90→90/90**、种子 43 的 **87→90/90**。这直接表明权重更新提升了读取**相同部分历史**的能力。

来源反馈也做了反事实：保留公开目标、模型选择的动作序列和检查点，只把每个已选动作的来源转移换成另一隐藏机制的真实转移，再生成 LoRA。两个 v3 种子在原反馈下均 **90/90**；换反馈后均 **0/90**，且 **90/90** 预测改变。说明该受控任务的收益依赖实际观察到的反馈，而不是只装任意 LoRA。此诊断在看到主要结果后执行，不增加独立测试组数。

这些仍然是用真实 `xminigrid` 转移搭建的**三机制、三候选动作、一步 tile 产物**任务；机制在训练期出现，测试留出的是规则内容和布局，不是未见机制或官方完整 XLand 通关。环境正式 reward 与 tile 产物在部分机制下不一致，不能把 90/90 称为官方成功率。

## 文本经验对照：优势与反例同时存在

在同一受控 XLand 90 个一步目标上，冻结 Qwen 只接收目标问题时 **30/90**；把同一三条来源的原始公开转移直接写成 JSON 文本是 **58/90**；把公开前后状态压成“各动作目标 tile 数量如何变化”的表述是 **60/90**。旧 [MemRL 对照报告](X_LAND_MULTI_MECHANISM_MEMRL_COMPARISON_20261005.md)的直接原轨迹文本为 59/90，两次放置文本的提示包装不同，均单独按各自协议报告。原完整历史超网络两个种子为 **90/90、87/90**，且测试目标提示不含来源文本。这支持一个具体瓶颈：**仅把轨迹放进提示，并不保证当前读者能把反馈变成正确动作**。例如 Qwen 在“动作 0 使目标 tile 数量 +1”的表述下仍普遍选动作 4；参数生成器的动作监督直接作用于未来选择，绕开了该读者的一部分运行时推断困难。

然而，当一个确定性外部提取器从**同一公开来源转移**明确写出“先前唯一产生目标 tile 的动作是 0/3/4”后，文本对照也达到 **90/90**。这个提取器没有读取目标题答案，但专门计算了本受控任务的目标 tile 增量，属于强结构化文本基线。故**不能声称 LoRA 在本质上比文本能表示更多知识，也不能说 XLand 已证明参数经验必然更准**。当前证据表明 LoRA 能把一部分“读转移→选动作”的运算在训练中摊销到参数生成器；若文本抽取同样准确，正确率优势消失。源文本作为目标提示的平均长度为：无历史 **225.2 token**、原始轨迹 **1045.6 token**、效果表述 **371.2 token**、明确结论 **282.2 token**。LoRA 目标提示与无历史相同，但生成器仍需先处理来源，不能只凭提示 token 断言总延迟更低。

ALFWorld 采用同一批第二批训练域普通放置 30 题、同一个冻结 Qwen、同一条已审核成功 sibling 来源、30 步、每步至多 64 新 token、最近两轮上下文、可用动作约束和官方 `won`。新增文本臂与原 LoRA 臂逐题绑定来源和初始观察；文本方案在系统提示放来源，LoRA 方案仅挂生成参数。结果：

| 单次官方通关，同一批 30 题 | 成功数 |
|---|---:|
| 无记忆 | 14/30 |
| 原生 MemRL 单来源写入、检索 | 19/30 |
| 直接放入正确来源的轨迹文本 | **20/30** |
| 冻结 Qwen 将来源概括为不含具体物体名的短文本后使用 | 13/30 |
| 原超网络、正确来源 LoRA | **25/30** |

| 正确来源 LoRA 与原始轨迹文本同时使用 | 20/30 |

正确来源 LoRA 与直接文本逐题比较：LoRA 独有胜利 8 题，文本独有胜利 3 题，双侧配对精确符号检验 `p=0.2265625`。正确文本与错配文本分别为 **20/30、12/30**；正确 LoRA 与错配 LoRA 则为 **25/30、26/30**。所以这里**可以说当前配置的参数接口数值上高于这些文本接口，但不能证明 LoRA 的额外五道胜利来自正确历史中特有的知识，更不能证明一般性优于文本经验**。30 条来源文本平均 **376.7 token**，每一步都会进入演员提示；自动摘要平均 **52.0 token**，但只有 13/30，说明当前摘要器损失了有效行为信号。这仅是一个固定提示的 Qwen 摘要器，不代表最佳文本 writer；LoRA 的来源编码和当前状态编码也有计算成本，尚未做总延迟比较。

对轨迹的事后诊断发现：在 30 题中，直接文本臂有 29 题发出过 `take`，其中 10 题的**首次** `take` 对象类别与当前目标对象不符；正确来源 LoRA 为 26 题发出过 `take`、其中 2 题首次对象类别不符。分类依据是目标题目录的目标物体类型，只用于评分后分析，不进入模型输入。部分文本失败轨迹把不相关物体带去目标容器；这与来源文本表面细节干扰当前目标相符，但不是已做完因果消融的解释。

LoRA 与直接文本逐题配对为：LoRA 独有胜利 **24**、文本独有胜利 **12**、共同胜利 **23**、共同失败 **75**；双侧配对精确符号检验 `p≈0.06525`。文本相对无记忆也增加总成功数（25→35），但其逐题新增／退化为 22／12，`p≈0.12145`。因此可报告**这套固定协议下 LoRA 数值上比直接读轨迹多通关 12 道**，但不能把它写成已达到常用显著性阈值的普遍胜利；两者在不同家族各有优势，且先前 ALFWorld 来源错配控制依然限制了“正确历史专属经验”的解释。134 条来源文本平均 **533.7 token**，每个行动步都放入演员系统提示；LoRA 的演员提示没有来源文本，但需要单独计算来源及当前状态的表示，所以这里也不声称总计算成本已经更低。

这一长评测初始单进程在保存了前 **55** 道完整题后由本轮主动 `SIGINT` 结束（退出码 130）；之后在空闲 GPU 上跑互不重叠的 **55–81、82–107、108–133** 三段。中断发生在第 56 道的未完成计算中，该道只在后续分段完整重跑并计分一次。`audit_alfworld_memrl134_direct_text.py` 按冻结目标顺序、来源和模型哈希检查四段，无缺失、重复或评分失败；合并结果 SHA-256 见下方本机记录。此分段只改变运行调度，不改变演员、历史或预算。

## 下一项真正困难的问题

v3 已在受控 XLand 证明**同一段部分轨迹被新参数读得更好**，但 ALFWorld 现有提升中错配来源仍略高，官方 XLand-100B 的后续环境奖励也未验证。若要主张“参数经验比文本经验更有用”，下一版应在**目标公开输入相同而历史反馈导致最优动作不同**的真实环境任务上优化正确／错配来源的后续**奖励差**。可将超网络写成 `Δ_t = Hφ(τ₁,…,τ_t)`，在训练划分里用同一目标、同一重置的环境回报优化 `E[R(πθ+Δ_t)−R(πθ)]`；对经审核确实需要不同策略的配对规则，再加 `max(0, m+R(πθ+Δ_wrong)−R(πθ+Δ_correct))`。只有当反事实历史改变真正所需动作时才施加后项，避免把 ALFWorld 中同样有效的另一条完成路线错当负样本。真实多步 reward 稀疏时，可先用经环境重放确认的动作做预热，再用配对真实回报更新，而不能直接把模型重新自答当正确标签。

评测要同时固定文本 writer 的训练投入、超网络训练数据、来源轨迹、目标演员、尝试次数、输入 token 与使用次数；报告来源编码耗时、目标提示开销和累计成本。仅提高 ALFWorld 通关总数或只胜过一个弱摘要器不够支撑参数接口的机制优势。

新实现入口是 `xland_online_novelty_v2.py`、`xland_prefix_hyperlora_v3.py`、`xland_online_replay_v3.py`、`xland_text_evidence_control.py`、`alfworld_replica30_direct_text.py`、`alfworld_replica30_text_summary.py`、`alfworld_replica30_hybrid.py`、`alfworld_memrl134_direct_text.py`、`alfworld_memrl134_direct_text_chunk.py` 与 `audit_alfworld_memrl134_direct_text.py`。所有新审核输入、逐题结果及权重只保存在 ignored `data/annotations/`、`results/`；仓库仅上传代码和本 Markdown 摘要。关键本机审计 SHA-256：v3 前缀审核 `ea0e96136c1d49a1f276bf14d1bb192c8670dc965881c2f66d94293f6f3fc6a8`，v3 种子 42／43 检查点 `dbbb5e74ddff1c0e08a5041b81e87b1c07d1041a7ebf1f2bede901e6c39bafb1`／`2f078a3a8446e30d964e8e922f09ac706c0803e58d7440c335dbc8e1db91dad3`，ALFWorld 134 题文本合并审计 `ec6a5d124f2d7df8d96ca676dbaf5a84d13b58657cee2e2c82a91e7deca10a17`。正式环境、数据与复现依赖按根目录 `EXPERIMENTS.md` 第 4 节准备；冻结原始记录不可覆盖。
