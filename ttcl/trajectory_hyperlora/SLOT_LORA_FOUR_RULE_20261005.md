# 四条件分槽 LoRA：轨迹读取与参数组合试验（2026-10-05）

## 问题与结果

前三标记的直接轨迹→LoRA 生成头即使接受同题换历史配对训练，也常把未见规则组合中的整类动作反过来。本轮改为每个条件关系占用独立的 rank-2 LoRA 子空间，四个槽合并为一份 rank-8 参数更新，挂在冻结 Qwen3-4B 的最后两层 `mlp.down_proj`。先用诊断规则读取器验证写入上限，再训练小网络从**原始成功轨迹的观察与动作字符串**读出四个关系位；第二阶段冻结第一阶段 LoRA。

四个标记共 16 种二进制动作组合。训练仅用 8 种偶校验组合 `0,3,5,6,9,10,12,15`；开发用 `1,2,4,7`，最终测试用 `8,11,13,14`。因此**完整组合**在训练、开发、测试间互斥；每个单独标记与动作的对应关系在训练中都出现过。测试还使用新采样的来源轨迹、不同的记录与查询措辞，以及训练数值范围之外的后续读数；来源数字本身可能与训练来源数字重合。每种测试规则有两条来源轨迹，每条问四标记 × 四个新读数，共 **128 个严格首动作 token 判断**。同一题配对比较无 LoRA、训练来源参数的公共平均、正确来源、只改变历史动作的相反来源；每条结果保存来源与查询内容 SHA-256。

原始轨迹读出器仅用训练来源的合成步骤标签监督：冻结 Qwen token embedding，分别编码每步观察和动作，预测标记与动作，然后按标记汇总为四位关系。两个种子在测试的 8 条新来源中均为 **32/32 关系位正确、8/8 整条来源正确**，所以挂载后的行为与诊断规则位完全一致。此结果支持一个限定结论：在小规模成功轨迹、固定动作词汇和可监督的条件槽位下，可以从新轨迹生成对未见完整规则组合有效的单份参数经验。它**不证明**模型能从混合失败的长轨迹自行分配信用，也没有用后续任务的环境奖励训练超网络。

开发集的短提示词使四臂在两种子上都先输出 `The`，按严格首动作 token 判分均为 **0/128**。这条失败记录保留，说明方法及评测强烈依赖询问格式；不能只报告最终测试正例。最终测试的完整规则组合已被查看，后续基于本结果改模型时不得把它继续当独立确认集。两种子共用同一数据规则与测试集合，也不足以给出真实任务的稳定成功率。

本轮与旧的三标记配对试验在任务数、架构、措辞和判分上不同，不作直接分数比较。新的正结果更准确地定位了上轮的瓶颈：**显式分槽的参数组合**能让单份 LoRA 使用多条独立关系；旧的混合生成头容易发生规则干扰。但当前分槽位置由合成标记和步骤监督给出，真实任务仍需学习可迁移的状态／动作关系槽位。后续应加入被拒绝动作与纠正、来源适用范围和新任务族；再用下一题的正确来源减公共／错来源配对效用训练低维参数生成器，最后进入 ALFWorld。对于提示词鲁棒性，也需预先固定新的确认题集，而不能看到结果后只挑有效措辞。

代码为 `slot_lora_oracle_pilot.py`、`slot_lora_raw_readout.py` 和逻辑测试。两阶段都只在空闲 GPU 3 运行，单进程显存上限为 35%；没有停止或修改其他卡上的实验。原始逐题记录、生成头与读出器 checkpoint 都在 ignored 的 `results/trajectory_hyperlora/{slot_lora_oracle_20261005,slot_lora_raw_20261005}/`，不上传 Git。四份结果 JSON SHA-256 依次为诊断种子 42 `1f65ed97af6a5027e108b523b76547027b927eeb512c8f28e3df50db5c2b5fb4`、诊断种子 43 `31f8c22108f5d4f932a463b6cce98a11b327322c7a409b6b188434a9a467a8cf`、轨迹读取种子 42 `fa6ec84c2fe844659aea7d8a7157134177b7f654481445446bb18d72699c3f86`、轨迹读取种子 43 `8d75dcc4a0617756b6317aa4bb668ed531a45a758240785c2cba4d539b3865ab`。
