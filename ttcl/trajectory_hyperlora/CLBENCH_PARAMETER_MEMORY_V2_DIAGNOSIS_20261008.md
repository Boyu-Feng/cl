# 轨迹→持久 LoRA 在 CLBench 的早期迁移诊断

## 当前能下的结论

这次是把 **仅在 ALFWorld 上训练的冻结超网络**直接接到 CLBench 的官方任务重置、JSON 动作接口和 `run_task` 评分上。每个领域从空参数记忆开始；只有自身回合的官方 `success=True` 才把其公开轨迹转成 LoRA，后续题只挂 LoRA 参数及选择键，不带旧轨迹文本。Qwen3-4B、超网络与 LoRA `A` 在 CLBench 均未训练。每个领域只看 seed 42 的前四个顺序实例，属于接口与早期趋势检查，**不是完整 CLBench 结果**。

在目前可完整评分的三个领域，这个 ALFWorld 检查点**没有显示 CLBench 收益**。频谱没有获得任何可写入来源；扑克写入后反而负迁移；数据库的后续行为改变但官方分数不变。Cohort studies 的完整四题配对尚未完成：完整历史的 8k、16k 预算先后溢出，短历史 512-token 输出不足以提交 36 队列 JSON；将两轮短历史、4,096-token 输出和 32k 上限组合后，首题无 LoRA 官方分数为 `−0.122167`，在线臂尚在运行时按用户要求停止，不能计算配对差值。Sales prediction、Codebase adaptation 的 Docker socket 当前不可访问，没有官方评分。

|---|---:|---:|---:|---:|
| Blind spectrum monitoring，8k | 4/4 | 0.22665 | 0.22665 | 0 |
| Exploitable poker，8k | 4/4 | −1.00 | −3.75 | 1 |
| Database exploration，16k | 4/4 | 0.10 | 0.10 | 1 |
| Cohort studies | 0/4 完整配对 | — | — | 无可比较结果 |

旧 8k 数据库试运行有 3/4 完整配对；第 3 题在线臂超过预算，分数缺失而非记作 0。随后两臂同用 16k 完成 4/4。两个有完整分数的版本都保留原始失败记录、预算、轨迹和分数；输入绑定与在线写入链的只读审计通过。上述三行预算不同，不合并成一个跨领域均值；四题小样本不足以估计稳定改进或退化。

## 为什么目前在 CLBench 不行

1. **训练目标与领域明显错位。** 冻结检查点自身标记 `training_domain='alfworld_retry_reward'`、`source_scope='sibling_expert'`、`train_task_pair_only=True`。它学习的是 ALFWorld 轨迹与后续环境命令之间的关系，没有在扑克下注、SQL 探索、频谱报告或队列 JSON 上学习过“哪类参数变化提高下一题的官方回报”。此处的 CLBench 推理不是 CLBench 超网络训练。
2. **成功门控无法利用连续反馈。** 频谱前四题的官方分数为 `0.2203/0.2482/0.2117/0.2264`，但官方 `success` 条件是 `score >= 0.5`，因此四题都不写入，在线臂始终与无记忆完全相同。直接改成“分数大于零就写”又可能把较差轨迹当作好经验；需要学习相对于当前策略与未来任务的效用，而不是固定跨领域阈值。
3. **轨迹格式与训练输入不同。** 扑克第 2 题是唯一真正写入的成功来源，其四步动作 JSON 共 2,614 字符，其中 `thinking` 字段占 2,414 字符（约 92.3%）；动作、下注额和反馈在来源编码中所占很少。数据库第 2 题的成功轨迹为 5,178 token，按既定 2,048-token 上限只保留头尾，丢失中间查询/反馈。ALFWorld 训练来源是短的自然语言命令轨迹；这两种输入会改变超网络看到的证据分布。
4. **写入后的参数确实改了动作，但方向不对。** 扑克第 3 题同题官方回报无 LoRA `−1`、LoRA `−4`；LoRA 分支在后段增加一次 `RAISE 30`。第 4 题无 LoRA `12`、LoRA `4`，开局无 LoRA `RAISE 30`、LoRA `CALL`。两题都没有 JSON 格式错误，所以这里不是“根本没挂上 LoRA”或动作解析失败。数据库写入后第 3 题在线臂从 7 次模型调用增至 14 次，第 4 题答案也改变，但两题两臂均得 0。更长或不同的动作轨迹不等于更多回报。
5. **当前读取门控在单来源时不能纠正错配。** 扑克和数据库的被影响题都只有一条已存来源，选择权重必为 1。当前任务的键只决定多来源混合，不会重新生成适合当前 JSON 任务的 `B`；所以这次负迁移不能归咎于多来源路由错误，主要问题在来源→参数方向及其跨题适用性。

## 是否需要 CLBench 训练

**如果目标是在 CLBench 上稳定有效，应该用 CLBench `train` 轨迹训练或微调超网络；但不必给每个领域单独造一套超网络。** 目前实验不能逻辑上证明“任何零样本迁移都不可能”，但现有超网络完全缺少 CLBench 的来源→未来回报监督，且已出现真实负迁移。只换记忆更新公式，缺乏依据能修好 LoRA 方向。

建议下一版先训练一个共享的多领域超网络，并保持测试时从空参数记忆开始：

- 从 **训练划分**的自身公开轨迹构造来源，保留规范化的实际动作、环境反馈和终局奖励；`thinking` 不作为主要动作证据。新来源格式必须重新审核输入内容绑定，不能沿用旧历史 ID 的标注。
- 把一条来源写入前后，在**后续训练题**上同预算、同目标题比较官方回报，使用 `ΔR = R(挂载 LoRA) − R(无 LoRA)` 训练生成器与写入/读取门控；连续奖励只由训练数据确定规范化尺度。加入退化惩罚与不写入选项，避免把一次成功全局套用。
- 混合扑克、频谱、数据库、队列研究与 ALFWorld 的训练来源，训练同一套接口和超网络；保留 ALFWorld 回放或约束，防止为了 CLBench 而失去现有 ALFWorld 收益。测试顺序、来源、目标题、预算和 checkpoint 预先冻结；测试时不再更新超网络权重，只按公开反馈更新参数记忆。

在开展这项训练前，还需要一个廉价的诊断消融：固定同一成功来源和后续题，仅移除扑克 `thinking`、比较数据库完整分段编码与当前头尾截断，并对照 `无 LoRA / 正确来源 LoRA / 无关来源 LoRA`。这能分清输入接口问题和超网络本身的跨域失效；上述消融目前**没有运行**。
