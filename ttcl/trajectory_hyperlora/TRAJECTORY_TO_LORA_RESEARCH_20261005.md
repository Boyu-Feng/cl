# 轨迹直接生成参数经验：下一阶段研究记录（2026-10-05）

目标是让一个共享生成器读取**已完成的原始公开轨迹**，产生可单独挂载的 LoRA；后续相似任务不再携带源轨迹文本。轨迹包括观察、动作、环境反馈和终局奖励，不要求先让语言模型撰写技能文档。底座保持冻结，生成器可以用监督预热和配对环境奖励训练。这是待验证的算法目标，不是已经取得的 ALFWorld／CLBench 分数。

## 与已发表方法的关系

- [LatentSkill](https://arxiv.org/html/2606.06087)：输入是文字技能，教师轨迹监督技能→LoRA 的生成器；不直接把新原始轨迹作为生成器输入。
- [Parametric Skills](https://arxiv.org/html/2606.30015)：成功轨迹先经总结、提取和验证成为文字技能，再由生成器转为 LoRA；还探索了在线合并参数经验。这是最接近的完整链路，但中间依赖文字技能质量。
- [SHINE](https://arxiv.org/abs/2602.06358)／[Doc-to-LoRA](https://arxiv.org/html/2602.15902)：支持“上下文→LoRA”的架构与蒸馏训练，但不直接证明复杂 agent 轨迹中的成功、失败和纠错能成为有益的策略更新。

本方向的区别是 **轨迹 → 参数经验** 的直接映射及其跨任务效用验证，而不是只问模型能否复述历史。不能把上述论文的结果当成本仓库方法的成绩。

## 对已有可行性实验的复核

[前一轮实验](EXPERIENCE_TRANSFER_FEASIBILITY_20261004.md) 的 7/8 需要按规则拆开理解。两个种子完全相同：规则 0 的基模 0/4、正确 LoRA 3/4；规则 1 的基模已是 4/4、正确 LoRA 仍是 4/4。整体的 4/8→7/8 增益全部来自规则 0。错配 LoRA 在两规则上分别是 0/4 和 1/4，说明有轨迹相关的参数作用，但“比错配 LoRA 好”本身不代表比基模好。因此新目标函数**只用候选与同任务基模的配对差值作为主奖励**；错配轨迹只作特异性诊断。

## 训练目标

令 `τ` 为已完成源轨迹，`x` 为在训练分割中随后执行的独立任务。生成器从 `τ` 产生一个分布 `qφ(z|τ)`，样本 `z` 决定 LoRA `Δθ(z)`。先用不含 `τ` 的输入执行相同 `x`：一次挂载该 LoRA，一次不挂；两次使用同一环境种子、动作预算和评分。由官方 reward 形成

\[
d_i=R(x_i;\theta+\Delta\theta(z))-R(x_i;\theta),\qquad
U(\tau,z)=\operatorname{mean}_i d_i
-\lambda\operatorname{mean}_i\max(0,-d_i).
\]

第二项惩罚负迁移。若某个 LoRA 仅把已有正确任务变坏，`U` 为负；若它只比错配 LoRA 好但没有超过基模，`U` 为零。尺度及 `λ` 只能在训练集定好。`paired_utility.py` 实现了输入绑定、缺失 reward 拒绝、逐任务配对和保留负收益的效用计算。

对于离散潜变量或随机生成的低秩参数，用 `-(U-b) log qφ(z|τ)` 更新生成器；可用只依赖训练数据的 baseline `b` 降方差。这是**轨迹级信用分配**：对生成的一整块参数经验是否帮助未来任务记账，不把失败轨迹的每个动作都直接标成错误。先以独立的后续任务动作或有历史教师的行为做预热，再用配对环境奖励微调。直接从稀疏终局奖励开始训练预计方差很大，此处是算法判断，尚非实验结论。

生成器建议从小的共享低秩基底起步，输出连续系数和置信度；在多任务上验证后再考虑逐层直接生成完整 A/B。部署时源轨迹仍要逐条保留来源、适用范围与历史效用；通过验证后按任务选择挂载，不把所有 LoRA 无条件相加。新任务的轨迹只能在协议允许的在线时点加入经验库，不能回流训练分割。

## 真实数据准备审计

`audit_alf_pairs.py` 只读取现存冻结计划的 ALFWorld **train** 游戏和原有 `training/delta` 日志。它检查训练与评测游戏无交集，把同一序列的 `task_0→task_1`、`task_1→task_2` 建为候选，并对源公开内容与后续任务初始公开观察计算 SHA-256；输出位于忽略上传的 `results/trajectory_hyperlora/alf_train_pair_audit.json`。这一步**没有创建监督标签**，每行标明 `reviewed_target=false`，历史后续任务 reward 也不能充当挂／不挂新 LoRA 的配对奖励。

本机冻结计划含 144 个 train 游戏和 36 个评测游戏，检查无交集。现存 Delta 训练日志共得到 96 个相邻任务候选对：74 个源任务失败、22 个源任务成功；历史后续任务 76 个失败、20 个成功。原日志总共 144 个任务，仅 33 个成功；按阶段分别为 13/48、9/48、11/48。`task_0→task_1` 的 48 对中，33 对两次都失败、7 对两次都成功、6 对成功后失败、2 对失败后成功。源数据十分稀疏且失败多，不能直接把“整条轨迹成功/失败”当可靠的动作级教师。

下一步所需的新证据是：在 train 划分中从这些候选及新采样任务建立**真正的同任务、同种子、同预算** `base / 正确轨迹 LoRA / 错配轨迹 LoRA` 回放；审核用于监督预热的目标，并把审核目标绑定到实际输入内容。随后才训练生成器和评估未见 ALFWorld／CLBench。GPU 当下还有空余，但缺少这组配对环境回放和新审核目标；本轮没有冒用旧后续 reward 训练 RL，也没有声称真实 benchmark 提升。
