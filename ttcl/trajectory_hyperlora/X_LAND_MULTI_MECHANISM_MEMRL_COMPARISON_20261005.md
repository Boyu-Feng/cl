# XLand 多机制轨迹参数经验与 MemRL 对比（2026-10-05）

## 要回答的问题

前一轮原始轨迹超网络只覆盖两种隐藏规则和固定布局。本轮扩大到三种 XLand 规则机制、改变来源和目标布局，并把同一公开目标状态分别配上三种相反历史。训练输入仅包含轨迹中的公开观察、目标、动作、下一观察、环境奖励及结束标记；目标策略在答题时看不到历史，只接收超网络生成的 LoRA。这里仍是**一步产物动作**受控任务，不是完整 XLand 任务的正式通关率，更不能直接推广到 ALFWorld 或 CLBench。

这套方法借鉴 [LatentSkill](https://arxiv.org/abs/2606.06087) 的“历史信息生成 LoRA，未来行为监督”，但不是其复现：LatentSkill 先从技能文本学习参数表示，再用轨迹监督；这里直接输入原始轨迹，优化未来动作交叉熵与配对间隔损失，没有文本技能文档预训练，也没有 RL。

## 数据与审计

使用真实 `xminigrid` 环境的 `AgentHoldRule`、`AgentNearRule`、`TileNearRule` 转移。每组的公开目标状态、目标产物、候选动作 `0/3/4` 相同，隐藏规则分别令正确的一步动作是 `3/0/4`。历史由三个独立的单步试验构成，分别试过三种动作；没有把机制类型、规则编码或人工计算的“哪个动作有效”标记交给模型。来源与目标的代理位置、面向方向、邻接方向会变化，但房间大小和两块物体的模板固定。三种机制在训练、开发、测试中都出现；留出的只是规则内容及具体布局，**不是未见机制泛化**。

审计脚本重新检查每个来源和目标试验的产物变化、动作、有限环境奖励、划分隔离和输入内容 SHA 绑定。审核后训练/开发/测试分别是 **108/49/30 组**，每组三问，即 **324/147/90** 个目标动作。另有 **18** 组候选未通过；它们的来源和目标公开观察没有形成要求的差异，失败记录保留在忽略的候选文件。审核标注 SHA-256：`12a31b7dee43801b47f8a364da649e9662bc0c90a1d961a148c79eebc1c46879`。原始数据、逐题结果和权重位于 Git 忽略路径，不上传。

一个关键反事实检查把每条历史中三次独立试验的顺序从 `0,3,4` 改为 `4,0,3`，保留每次试验的动作、环境反馈、目标问题和审核标签。审核脚本为变换后的模型输入重新计算内容 SHA，且再次验证真实转移。因此测试成绩不应依赖三次试验碰巧处于固定槽位。

## 方法与对照

小型策略实验把轨迹编码为 `z`，再产生秩 8 的 LoRA 因子 `B=H(z)`，以 `W+2BA/8` 改变冻结动作策略。旧编码器把所有事件串接并加全局位置；新编码器先独立编码每次试验内部的有序事件，再对试验表示求平均，使独立试验的排列不改变 LoRA。策略主干和动作输出层随机初始化后冻结，输入编码器、轨迹编码器与超网络参与训练。

小模型两种子均训练 2000 步，学习率 `0.001`；Qwen 两种子均训练 600 步，学习率 `0.0003`。四个新检查点的配对损失权重均为 `1`、margin 为 `1`。开发集选检查点，留出测试和顺序变换只作评估。

Qwen 实验冻结 `Qwen3-4B-Instruct-2507`，把生成的秩 8 LoRA 装到最后两层 MLP 的 `down_proj`。相同的未来动作监督和配对损失用于训练；开发集选检查点，测试集仅评估。`错历史` 用同一道公开问题中另一规则的历史，`空历史` 完全不装 LoRA；二者控制“加载任意参数也有效”和原模型自身会答题的可能。

MemRL 对照使用仓库原生的程序性经验写入、BGE 检索和 Q 更新服务，读者是同一个冻结 Qwen，并使用同一目标问题提示。训练记忆只从训练组预载入；每个测试历史从相同训练快照恢复后再独立写入，避免测试历史相互泄漏。还记录不带记忆、错配记忆、直接把原始历史放进提示的诊断。其写入过程沿用 XLand **正式环境奖励**，而本轮评估指标是“一步产生目标 tile”；这两个信号并非处处一致，因此 MemRL 数字是适配后的机制对照，不能当作官方 MemRL 或 XLand 排行成绩。

MemRL 程序性写入的生成上限是每条 256 token，检索最多 3 条记忆，读者上下文预算 2048 token；训练和测试采用相同设置。测试集的 90 次写入均有记录，无空检索上下文。

两路训练/预载入预算也不同：超网络使用训练组全部三条反事实历史，即 324 条标注目标问题；MemRL 预载入每组一条历史，共 108 条，然后在各测试分支写入当条新历史。后者避免训练记忆里直接放同一个目标的三条相互冲突经验，但两路数字只能说明这个具体协议下的表现，不能单独归因于“参数经验一定优于文本经验”。

## 已完成结果

| 模型与编码方式 | 种子 | 原顺序测试：正确/错历史/空历史 | 打乱试验顺序：正确历史 |
| --- | ---: | ---: | ---: |
| 小型冻结策略，全局位置编码 | 42 | 90/0/30（均以 90 为分母） | **30/90** |
| 小型冻结策略，试验顺序不变编码 | 42 | 90/0/30 | **90/90** |
| 小型冻结策略，试验顺序不变编码 | 43 | 86/1/30 | **86/90** |

旧模型原顺序 90/90，看似完美；一旦仅改变独立试验顺序就回到 30/90，且错历史也预测成相同动作。可见这个成绩主要利用了试验固定位置的捷径，不能拿来证明泛化提取经验。修正后的两个种子在顺序变换前后逐题预测一致，分别达到 90/90 和 86/90；错历史接近 0/90，说明来源内容确实控制动作。但由于动作候选只有三种、每个候选都在历史中试过一次，这仍是简单受控场景。

冻结 Qwen 的结果如下。两个新编码器检查点都由开发集第 200 步选出，原顺序与重新排列的逐题预测完全一致。

| Qwen 超网络 | 种子 | 开发集 | 原顺序测试 | 重排试验测试 | 错历史 | 空 LoRA |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全局位置编码 | 42 | 147/147 | 90/90 | **30/90** | 0/90 | 30/90 |
| 全局位置编码 | 43 | 147/147 | 88/90 | **31/90** | 0/90 | 30/90 |
| 试验排列不变编码 | 42 | 147/147 | **90/90** | **90/90** | 0/90 | 30/90 |
| 试验排列不变编码 | 43 | 144/147 | **87/90** | **87/90** | 3/90 | 30/90 |

旧 Qwen 的原顺序高分同样是固定位置捷径；仅改变历史试验顺序就回到约三分之一。修正后的两个种子在相同扰动下保持成绩，并对错配历史改变动作。这支持本设置中“轨迹信息经 LoRA 影响后续动作”，而不是证明跨未见机制或长期环境回报的泛化。

MemRL 对照的 108 条训练记忆写入后被冻结为快照；每个测试分支从该快照恢复，再写入本条历史。测试部分曾在全部 30 组完成后因最终结果序列化时的变量重名报错，因而修复代码并从**同一训练快照**重跑测试，没有重训记忆。快照 SHA-256 为 `94eb28a59c09d034cb76d315a5d1c11c3258014d6289ec89700b88e0d78178c6`。重跑每组即时保存逐题记录，最终输出通过校验。

| 冻结 Qwen 读者的输入 | 正确数/90 | 作用 |
| --- | ---: | --- |
| 不给历史或记忆 | 30/90 | 基模机会水平 |
| 原生 MemRL 检索的经验摘要 | **30/90** | 程序性写入、BGE 检索、Q 更新 |
| 同一问题的错配 MemRL 经验 | 30/90 | 来源对照 |
| 直接放入原始历史轨迹 | **59/90** | 不经过经验写入与检索的诊断 |
| 放入错配原始历史 | 1/90 | 来源对照 |

这轮 MemRL 的 90 次测试写入中，**刚写入的本条经验 0 次被检索出来**；检索上下文始终非空，但三个动作分支都预测 `4`。查询仅概括目标产物，许多训练记忆在嵌入空间很相似，已有条目又被正式奖励驱动的 Q 分数排在前面。更关键的是，本轮一步评估按“动作后产物出现”计分，而正式 XLand 目标是持有产物；`AgentNearRule` 和 `TileNearRule` 可以产生目标 tile，却通常得到零环境奖励，MemRL 写入器会把它们当成未成功经验。这解释了本适配协议的低分，但无法区分“摘要内容本身是否足够”与“检索门控没有放行新摘要”。因此只能说**在这套适配和预算下**顺序不变 LoRA 优于该 MemRL 对照及直接读轨迹；不能据此声称普遍优于 MemRL。

## 复现与结果边界

代码依次为 `collect_xland_multi_mechanism.py`、`review_xland_multi_mechanism.py`、`prepare_xland_trial_order_probe.py`、`train_xland_raw_hyperlora.py`、`train_xland_qwen_hyperlora.py`、`evaluate_xland_qwen_checkpoint.py`、`evaluate_xland_memrl.py`。新候选、审核标注、权重和逐题输出均写入仓库约定的 Git 忽略目录。正式规则集资产、划分及安装步骤见 [上一轮报告](RAW_TRAJECTORY_HYPERLORA_XLAND_20261005.md) 和 `EXPERIMENTS.md` 第 4 节。

下一项必要验证是给 MemRL 增加“刚写入经验可见”的诊断，并设计同时保留官方奖励和本轮一步产物判定的对齐反馈；这能拆开写入、检索与反馈不一致的作用。还需要未见规则机制、更复杂的来源轨迹以及完整多步后续回报，才能主张通用的在线参数经验学习。
