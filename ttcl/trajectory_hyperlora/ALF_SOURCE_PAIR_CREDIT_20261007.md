# 同题换自身历史：从终局回报定位可训练的动作信用

上一轮 42 个首个动作分歧来自“旧 LoRA 成功／无 LoRA 基模失败”，其中 14 个在固定后续策略下有负向动作干预结果。它们的正负动作标签对历史来源并不变化；只用这组数据训练，容易学成通用动作偏置，而非从轨迹提取条件经验。本实验转向已有的、经审核的官方 ALFWorld **训练域** 8 条自身成功轨迹 × 18 道未来题目回报矩阵。该矩阵有 10 道题的终局胜负随历史来源变化；8×12 不重叠目标题已有独立矩阵，继续留作开发验证，不从中挑本轮动作。

对每个胜负随历史变化的目标题，按固定规则从获胜历史和失败历史的轨迹中选**最早的首个动作分歧**，并用来源 ID 决定并列顺序。新的 10 条候选绑定了原始 8×18 标注、两个来源轨迹、原游戏文件、完整回合、共享前缀、动作和检查点哈希。原 ALFWorld 环境重放共同前缀后，两种候选动作都合法；10/10 审核通过。选择规则只读取训练域矩阵，未使用本轮干预结果或留出题奖励。

每题先用原冻结演员和**获胜历史**完整重跑参考轨迹；随后仍用同一历史、相同目标、相同演员和 50 步／每步 64 token／两轮动作历史／两次重复抑制预算，只在首个分歧处强制换成失败历史选择的动作。以 $h^+$ 表示获胜历史、$a^+$ 和 $a^-$ 表示两条历史在同一状态首次分歧的动作，测量的是

$$
A_{h^+}(s,a^+,a^-)
=R(\pi_{h^+}^{\operatorname{do}(a^+)})-
 R(\pi_{h^+}^{\operatorname{do}(a^-)})\,.
$$

这只是在给定历史、演员和预算下的局部动作作用，不是环境的通用最优动作标签，也不等于两条不同历史策略的整回合奖励差。实际结果为 **3/10** 替换后从成功变失败，**7/10** 替换后仍成功；10 个完整反事实回合经独立原环境重放，零错误，运行零基础设施故障。三个局部作用案例的目标 ID 为 0、8、16，分别属于查看、清洗、双物体类别。其余七个案例不能据整回合胜负强行惩罚首个分歧动作：后续策略可能纠正这一步，也可能有更晚的关键决策。

这个结果将下一版训练目标分成两层。整回合层面，8×18 的同题多历史回报可监督**轨迹—目标题效用**，因为固定目标和演员后只换了历史；但终局差不能无条件摊给所有动作。局部层面，经干预支持的三个状态可监督有符号动作间隔。令 $z_\phi(h,q)$ 为超网络从历史 $h$ 和当前上下文 $q$ 生成的 LoRA 代码，$m_\phi(h,s)=\log\pi_{z_\phi(h,q)}(a^+|s)-\log\pi_{z_\phi(h,q)}(a^-|s)$。候选训练损失可以让获胜历史的 $m$ 高于失败历史的 $m$，并用有效矩阵范数／动作 KL 控制尺度；对干预后仍成功的七例，不把 $a^-$ 赋强负标签。这样目标显式依赖**两条不同自身轨迹**，可与来源置换、固定来源、无记忆及文本历史对照区分通用策略偏置。公式目前是待训练假设，不是已验证的新算法效果。

为量化“统一好来源”与“当前题匹配”各占多少，`analyze_alf_source_reward_interaction_v1.py` 在两个**已审核、每个来源均做全部目标题**的二元回报矩阵上做精确双向最小二乘分解：$R_{st}=\mu+\alpha_s+\beta_t+\gamma_{st}$，其中交互项 $\gamma$ 的行列均值为零。训练域 8×18 矩阵的中心化平方和中，来源主效应占 **1.81%**、目标题主效应占 **54.68%**、来源×目标题交互占 **43.51%**；不重叠的 8×12 题上分别为 **1.94%／58.91%／39.16%**。交互项第一奇异方向分别只占其能量的 **44.13%／51.34%**，说明单个统一标量难完整表达观察到的配对差异。两组逐题事后 oracle／最佳固定来源分别为 **15/18／12/18**、**8/12／5/12**，oracle 只能表示潜在上限，测试时不可读取目标题奖励。这些比例是固定样本上的**描述性方差分解**，不提供统计显著性、可学习性或在线更新收益的证明；二元回报残差也会把采样噪声和未建模因素计入交互。它们只支持下一版必须检验任务条件效用，而不能只学习哪条历史总体最强。

限制仍很大：只有三个强局部标签；获胜来源与动作差异共变，不能把某条历史里的具体反馈字段确定为胜因；原 8×18 矩阵虽然目标题与新生成器训练分开，但部分游戏在旧检查点候选集中出现过，完整血缘须参考既有矩阵审核。最重要的是，本轮**没有更新超网络权重**，尚未证明持续跨题更新 LoRA 优于固定首条历史或文本经验。下一步需要增加不同自身历史与未来题目的真实回报交叉矩阵，对训练域做源置换和多步干预，并在冻结的官方验证题序测更新后的环境胜率。

复现顺序：先按 `EXPERIMENTS.md` 第 4 节恢复公开资产及旧检查点和自身轨迹，生成并审核 `alf_own_success_future_reward_8x18` 与不重叠的 `holdout_8x12_v3c_merged`；然后运行 `prepare_alf_source_pair_action_v1.py`、`audit_alf_source_pair_action_v1.py`、`probe_alf_source_pair_action_v1.py`、`audit_alf_source_pair_intervention_v1.py`、`analyze_alf_source_reward_interaction_v1.py`。各脚本均需从仓库根目录以 `python -m ttcl.trajectory_hyperlora.<脚本名>` 运行，并使用第 4 节的主线 Python 环境。原始轨迹、审核结果和权重依仓库规则留在 Git 忽略目录，只上传代码与本摘要。
