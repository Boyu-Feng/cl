# 类型化来源证据与联合读取门控：v17–v20

## 目标与保留版本

v16 的证据单元和读门控只处理 JSON 对象数组。这里保留 v16 原文件与冻结结果，另用 v17–v20 逐步扩展到数值、类别值与文本命令。超网络检查点和逐题写入参数记忆的流程不变；新门控在同一步比较“证据候选动作”与已有 LoRA 路径，只有学到正的保守效用估计且候选通过当前公开 schema 时才使用证据，否则继续走 LoRA。没有任何 CLBench 领域名或特定动作字段出现在证据表示和算子中。

## 证据、候选操作、训练目标

每个证据单元为 `(类型、JSON Pointer 路径或文本根路径、值、来源题序、轨迹/动作/反馈 SHA-256、来源奖励、来源查询)`。提取器递归保留 JSON 数组和叶值；纯文本动作保留为文本证据。来源索引必须早于当前题，审计可从已执行的公开轨迹重建证据。当前算子有对象或标量数组的精确去重合并、数值平均、数值复制、类别值复制、文本提示候选，以及隐式“弃权后使用 LoRA”。任何会改写 JSON 的候选都要先通过当前公开 schema。

对一条证据 `e`、当前查询 `q`、基础动作 `a` 与算子 `o`，用训练/开发题的官方配对奖励差 `ΔR_o = R(a_o)-R(a)` 拟合各算子的线性效用模型。门控计算 `Û_o = w_oᵀ φ(e,q,a,o)`，再减去该算子训练残差绝对值的 90% 分位，选取下界最高且大于零的候选；未训练过的算子直接弃权。这个残差阈值是经验保守门槛，**不是有覆盖率保证的置信区间**。它阻止“仅因历史里有同名字段就复制旧答案”。

频谱数组标签沿用已审核的 20–55 训练、56–79 开发来源—目标题奖励差；8–19 不进入门控拟合或选参。Cohort 数值标签只用官方训练索引 0–5、开发 6–7：从完整的自身公开轨迹提取最终 108 字段提交，对此前自身轨迹的同路径数值分别尝试平均/复制，候选重新经过官方提交 schema 和评分；每条标签绑定来源/目标轨迹、动作和反馈哈希、目标实例及输入内容哈希。索引 8–19 未用于训练这些数值算子。

## 已完成结果与发现

- v17 将类型化证据接入在线演员，但比较用的冻结演员候选偶尔输出非法 JSON，异常未回退：频谱 8–19 只有 6/12 配对可评分。这是实现失败，原报告保留，不能计作方法收益。
- v18 修复候选无效时的安全回退。频谱 8–19 的 12/12 官方配对为无记忆 `0.22212`、在线 `0.25975`，8 次 LoRA 写入、0 次失败；与 v16 学习选证据逐题奖励相同。来源、动作 schema 和官方评分独立审计通过；报告 SHA-256 为 `47738132f3c7f3b8f226afcfd22cfe5b2a889c61d31388fa6a7faf8e5cb16ba6`。它证明扩展后的路径没有丢掉频谱既有收益，尚未证明新的数值/文字算子有收益。
- v19 在官方 Cohort 0–7 训练/开发段得到 2042 条训练与 2370 条开发数值候选标签，另保留 180 条频谱数组训练标签。数值平均在开发集 1185 个候选中有 550 个正差、626 个负差；直接复制有 487 个正差、693 个负差。保守门槛在开发集**两种数值操作都选 0 条**；频谱数组操作在 156 个开发候选中选出 116 条，全部为正差。模型 SHA-256 为 `6a578b8086132a3d3bccc8b7733fc21cfb5769b2794457c3a0ae78c93cdd66b5`。这些是操作级离线标签，不等于完整在线回报。
- v19 的初始在线试验因发现数值复制与字符串复制共用一个操作名而主动中断。v20 把类别值复制隔离为独立、未训练的操作；不能让数值标签授权复制命令或类别字符串。文本提示已能作为候选表示，但还没有 ALFWorld 命令提示适配器和已审核的效用标签，因此不会自动启用。
- v20 用联合模型在频谱 8–11 的 4 题在线小段复测，`0.22590→0.24170`，4/4 可评分、2 次 LoRA 写入；1 次选用 `array_union`，其余交由 LoRA/原演员。来源、schema 与官方评分审计通过，报告 SHA-256 为 `da62bfd2e5d0dddbaa80d5fa6ef61f8d98817abcb12dc6b776eafff728152104`。这只验证联合模型保住已训练的数组路径，不构成数值操作在线收益。

## 范围与待补结果
