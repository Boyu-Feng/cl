# 轨迹直接生成 LoRA 因子的组合泛化试验（2026-10-05）

## 结论

这个受控合成试验尚未得到稳定的正结果。直接从轨迹生成新的 LoRA 因子，在种子 42 的改进训练下，未见规则组合的正确率由 50% 无历史基线升至 66.7%；但种子 43 仍为 50%，而且对错轨迹不敏感。因此不能声称已经学会从任意新轨迹生成有效参数经验。没有运行 ALFWorld／CLBench 官方评测，也没有训练 RL。

## 任务与方法

合成环境有 `ALPHA/BETA/GAMMA` 三个标记；每个标记对应 `LEFT/RIGHT`，共八种完整规则。每条源轨迹包含每个标记四条成功的观察、动作、反馈记录。六种规则用于训练（编码 `0,1,3,4,6,7`），完整规则 `2,5` 留出。询问使用源轨迹没有出现的读数和新的措辞；挂载 LoRA 后，演员提示词不含源轨迹。冻结 Qwen3-4B 底座，仅训练轨迹编码器、共享 LoRA `A` 因子和由轨迹生成 `B` 因子的超网络，在末两层 `mlp.down_proj` 挂载 rank-4 更新。这里没有预训练的逐规则专家 LoRA 库。

训练目标是后续正确动作的监督交叉熵。初版每次更新只问一个标记；改进版同一次更新分别问三个标记，对每个损失取平均，避免生成的 LoRA 只照顾当次抽到的标记。测试比较无历史、把轨迹放入提示词、挂正确轨迹生成 LoRA、挂相反轨迹生成 LoRA。每个分割选两种完整规则，各用两条新源轨迹，每条询问三种标记 × 四个新读数，共 48 个判断；首词严格匹配动作。留出规则在训练时完全没出现，但其单个标记与动作关系在其他规则中出现过，因此这是**规则组合**泛化测试，不是全新动作或任务类型测试。

| 训练与分割 | 无历史 | 文本轨迹 | 正确生成 LoRA | 相反轨迹 LoRA |
| --- | ---: | ---: | ---: | ---: |
| 种子 42，单标记训练，已见规则 | 24/48 | 48/48 | 28/48 | 26/48 |
| 种子 42，单标记训练，留出规则 | 24/48 | 48/48 | 20/48 | 18/48 |
| 种子 42，三标记联合训练，已见规则 | 24/48 | 48/48 | 32/48 | 16/48 |
| 种子 42，三标记联合训练，留出规则 | 24/48 | 48/48 | 32/48 | 16/48 |
| 种子 43，三标记联合训练，已见规则 | 24/48 | 48/48 | 24/48 | 24/48 |
| 种子 43，三标记联合训练，留出规则 | 24/48 | 48/48 | 24/48 | 24/48 |

种子 42 的联合训练在每个分割中都把两类标记答对、另一类系统性答反。种子 43 的生成 LoRA 在全部测试中只答 `LEFT`；它对正确与相反轨迹的结果相同。训练后 100 步平均损失分别为 0.213 与 0.361。种子差异及这些逐标记错误表明，训练目标更完整虽有帮助，当前架构和优化仍未可靠抽出三组条件关系。文本轨迹 48/48 说明测试问题并非本身无法回答，也不证明参数法已经超过文本法。

本地原始输出、每条源轨迹和询问的 SHA-256、分割及期望动作保存在 ignored `results/trajectory_hyperlora/direct_composition_20261005/`。代码在 `direct_composition_pilot.py`。原始模型、数据和权重不上传。未进行官方 benchmark、统计显著性检验或独立训练集复验；两个种子和同一测试集只能作探索性诊断。

## 下一步

## 后续定位：关系提取与动作目标

为区分瓶颈，增加三种训练目标：仅在 `LEFT/RIGHT` 两个 token 间做对比、在全词表中监督实际生成的首动作 token、以及监督该动作 token 后紧接结束 token。基模实际生成的首 token 是无前导空格的 `LEFT`（ID 22397）；初版序列目标却用了带前导空格的动作 token。两动作对比目标导致模型在整个词表里优先输出题目数字，正确率为 0/48；只监督首动作 token 则在原始轨迹版本中退化为反复输出 `LEFTLEFT...`，严格动作正确率仍是 24/48 或更差。这些是输出目标设计问题，不能用训练损失代替实际生成评测。

为检查参数生成器的上界，加入**仅用于诊断**的解析器：它从合成源记录中准确读出三个标记分别对应的动作，形成三个 ±1 位，再通过线性映射生成 LoRA。它在测试时也使用解析器，因此**不是**端到端轨迹学习。两个种子使用“动作 + 结束 token”目标，在完整留出的规则组合上均达到 40/48；相反源轨迹为 8/48，无历史 24/48。这表明生成、挂载和组合使用 LoRA 有能力在此任务上起作用。

随后只在**训练阶段**用解析器产生三位关系辅助标签，在测试时让原始轨迹编码器独立提取。种子 42 的“动作 + 结束 token”版本训练损失降到 0.0004，但留出组合仅 16/48；相反源轨迹为 32/48。关系探针逐位仅 16/24：两种留出组合分别被误读成训练中已见的组合 `1` 和 `6`，而已见组合的关系均正确。因此主要失败点是原始轨迹的条件关系表示未能组合泛化；训练集近零损失掩盖了这点。当前没有证据说明引入 RL 就能自动修复表示错误。

| 追加试验 | 已见规则：正确/错轨迹 | 留出规则：正确/错轨迹 |
| --- | ---: | ---: |
| 仅两动作对比，原始轨迹，种子 42 | 0/48，0/48 | 0/48，0/48 |
| 首动作全词表损失，原始轨迹，种子 42 | 24/48，24/48 | 24/48，24/48 |
| 首动作损失 + 关系辅助监督，原始轨迹，种子 42 | 1/48，0/48 | 0/48，0/48 |
| 动作 + 结束 token + 关系辅助监督，原始轨迹，种子 42 | 32/48，16/48 | 16/48，32/48 |
| 准确关系诊断解析器，种子 42 | 38/48，10/48 | **40/48，8/48** |
| 准确关系诊断解析器，种子 43 | **40/48，8/48** | **40/48，8/48** |

## ALFWorld 直接接入诊断

把上述已训练的**原始轨迹**超网络（种子 42，动作 + 结束 token + 关系辅助监督）保存后，直接接到 Qwen3-4B 的 ALFWorld actor。来源是一条官方 ALFWorld `train` 场景的完整成功轨迹；两个目标是同一家族但不同的 `train` 游戏。超网络在 ALFWorld 上没有更新。每个目标分别从全新环境重置运行无 LoRA 和挂源轨迹生成 LoRA 两臂，贪心解码，最多 10 步；来源、游戏、checkpoint 哈希及完整输出保存在 ignored `results/trajectory_hyperlora/alfworld_zero_shot_20261005/seed42_probe.json`。

| 目标 | 无 LoRA | 挂合成任务超网络生成的 LoRA | 动作轨迹 |
| --- | ---: | ---: | --- |
| `look_at_obj_in_light`，Pencil | 成功，5 步 | 成功，5 步 | 逐步相同 |
| `look_at_obj_in_light`，Pillow | 10 步未完成 | 10 步未完成 | 逐步相同 |

这是小规模、10 步封顶的跨任务诊断，不是官方 ALFWorld 成功率。没有观察到收益，也没有观察到动作退化；它支持“合成超网络直接零样本迁移到 ALFWorld 尚无效果”的判断。下一步需要在不触碰官方测试集的 ALFWorld `train` 轨迹上训练或自监督预训练泛化的轨迹关系编码器，再用隔离的开发游戏做同预算配对评测。若尝试 RL，应先让随机 LoRA 使用与不使用在训练环境中有可测的配对奖励差，并记录每次源轨迹与目标任务的内容哈希；不能用合成任务奖励冒充 ALFWorld 奖励。
