# CLBench 未提升领域的诊断与混合参数记忆复测

## 问题与实验边界

目标是检查“频谱／数据库没涨分是否只是没在对应领域训练”，修复此前没有完整配对结果的 Cohort 接口，并在不改官方任务与评分的条件下继续验证轨迹→LoRA。保留 v2/v3 检查点和入口，所有新方法写入独立文件。基模为冻结的 Qwen3-4B-Instruct-2507；测试从空记忆开始，完成一题后只把自己的公开轨迹用于下一题。训练标签只用索引 0–7，后续题目不回流训练。每题用官方 `reset_baseline_instance`、动作 schema 与 `run_task` 奖励。在线写入门控能看到每题终局 reward，属于本仓库既定的 reward-visible 变体；对标准隐藏终局分数的 Cohort 排行设置不直接适用。不同领域奖励尺度不同，不合并成总均分。

## 对无效原因的复核

- **频谱并非完全没做领域训练。** 原 CLBench v2 已有 5 条频谱训练动作与 2 条开发动作，但用当次模型动作做目标，目标本身几乎只重述当前扫描。单条旧轨迹、累积旧轨迹作为提示，在索引 1–7 的官方分数均与无历史相同；加大旧 LoRA 强度到 1.5 倍也没改变分数，4 倍则产生无效 JSON。仅增加写入或强度不会自动教会模型恢复长期占用区域。
- **历史里确有有用的事实。** 在训练／开发索引 1–7，把当前提交中的对象数组与此前公开提交的同名对象数组合并，不读取测试私有状态，随后用官方频谱评分函数重新计分：7/7 均提高，单题增量为 `+0.0488,+0.1266,+0.1300,+0.1251,+0.1364,+0.0873,+0.0956`。这是训练候选动作诊断，不能冒充 LoRA 结果。候选生成只认 JSON 数组中的对象，不按领域名列出发射器规则。
- **数据库样本与演员都受限。** 原 CLBench v2 数据库只有 2 条正分训练动作。开发题 6–7 的首条零分轨迹冷启动写入后，下一题 SQL 动作改变，官方分数仍为 0；把当题历史从 2 轮增到 16 轮仍为 0；上一题原文与累积历史原文作为教师，在训练／开发题没有正向回报差，且一题 `0.4→0`。现有 4B 演员经常对不存在的表重复查询，不能把更多同类失败动作直接当优质监督。
- **Cohort 确实缺本领域超网络训练，但先遇到轨迹质量瓶颈。** 按官方训练索引 0–7 独立收集 8 条基模自身轨迹：7 条可评分，其中只有两条略正分（`0.005666`、`0.002595`），其余五条为负；另有一条动作不符合 schema。收集报告 SHA-256 为 `2a8211608a41343619cc76b70af21df8f5c293808c82b6796b6f866d8c073c91`。因此不能把 Cohort 的停滞简单归因于“训练步数少”；可靠领域训练还需要更多可验证的有效轨迹，不能拿测试段反向挑标签。

## 新版：累积轨迹监督与精确事实优先

频谱 v4 以索引 1–5 为训练、6–7 为开发，使用上述公开动作数组候选作后续动作监督，先验检查候选确实提高官方训练域奖励，再逐条审核来源轨迹哈希、动作 schema 和输入内容绑定。超网络从 CLBench v2 检查点继续训练，冻结基模；测试时从空历史起，每次正分后用截至当时自己的公开轨迹重算一个 LoRA，演员只挂参数、不重读历史文字。40 步开发目标交叉熵 `0.5515→0.5110`，但官方测试 8–19 的 12 题仍 `0.22212→0.22212`。另保留 v5，在相同已审核目标上追加 200 步，开发交叉熵 `0.5110→0.4510`；20–31 的 LoRA 动作开始改变，但两个任务的输出不合官方 JSON schema，不能把只筛完成任务后的微小正差当成总体提升。回退冻结基模后，12/12 可评分，纯参数版仅 `0.21231→0.21314`。

因此另设不解释字段含义的**精确事实侧记忆**：当公开动作 schema 的某个字段是“对象数组”，并且自己以前确实执行过同名对象数组动作，系统把此前对象项按精确 JSON 去重后加入当前动作。来源必须是过去已执行的公开动作；当前任务的官方评分、潜在状态和未来轨迹不进入记忆。v10 用同一条规则决定读取顺序：有可匹配对象数组时由冻结演员生成当前动作，随后并入事件项；其他动作继续使用原 CLBench v2 轨迹→LoRA 超网络及运行中回报写入门控。无效 LoRA 动作可以回退冻结演员。这个 JSON 数组侧记忆是**显式结构化事实保留**，不是 LoRA 学会了精确数值；它不覆盖非 JSON 命令，也未证明可泛化到所有结构化动作。

## 以有效统一入口继续：Cohort 领域适配

v13 直接继承 v10/v11 的结构化证据优先、正奖励写入、LoRA 读取和长来源截断，仅对生成动作增加当前公开 JSON schema 校验与冻结演员回退。Cohort 顶层动作是工具调用或当前任务的数值字段，没有频谱那种可直接补全的对象数组，因此该领域主要检验原 v10 的参数分支。原 v2 检查点和领域训练检查点各自从空记忆跑同一固定 8–19 题，保留所有格式失败。

领域训练 v15 沿用原 v2 的后续动作交叉熵目标和旧 17 条已审核 CLBench 标签，另外加入 Cohort 训练段两条自身正分轨迹的**最终提交动作**：索引 5 作训练、索引 7 作开发；每条都核对了公开来源哈希、动作与响应一致、108 个有限数值及官方 schema。训练 80 步，冻结基模，Cohort 开发目标的 LoRA 交叉熵 `0.0283→0.0265`，全开发集均值 `0.1185→0.1086`；这只是动作监督损失，不能代替在线奖励。直接训练 v14 在第 20 步因本轮 GPU 显存上限中断、未产出权重；v15 使用激活检查点及本轮空闲卡上的更合适限额完成，原 v2 权重未覆盖。两条正分轨迹远不足以宣称充分领域适配，在线结果完成后另列。

## 通用证据格式与可学习读取原型 v16

新记忆单元记录公开动作的 schema 路径、对象内容、来源任务与轨迹／动作哈希、公开反馈哈希、来源奖励和顺序。没有领域名或手写的发射器／医学字段。读门控的八个通用特征包括新增对象数量、重复率、对象键重合、任务文本词重合、来源奖励和时间距离；用同一训练题“合并单条旧证据／不合并”的官方奖励差拟合带正则的线性效用估计，预测效用大于零时只选预测最高的一条。LoRA 分支仍用原 v10 权重。

门控训练使用**已在更早研究中暴露**的频谱 20–55 题，180 个公开来源—目标题配对；56–79 的 156 对只选正则强度，8–19 未进入这次门控拟合或选择，但其任务曾用于旧方法研究，属于门控隔离复测而非研究者盲测。训练与开发效用分别约 94%／93% 为正；开发 11 条负例中，当前线性门控一条也未预测为负。因此它现在主要是**学习排序**，未证明能可靠拒绝坏证据。官方本地频谱序列只到索引 79，随机种子不改变任务内容；不能虚构 80+ 新题结果。

在频谱 8–19 的完整 12 题在线复测中，无记忆 `0.22212`，学习式选证据 `0.25975`，12/12 可评分、8 次 LoRA 写入；逐题来源、生成后字段合并、目标哈希和官方评分的独立审计通过。**只选历史最高奖励证据**在相同题上也是 `0.25975`，12 题执行动作逐字段相同；合并全部来源则为 `0.26053`，略高于两种单条选择。三组来源与官方评分审计均通过，报告 SHA-256 依次为 `4ae26aa824863d64a23254a5fdf5e2e8816ba1f39ef1d24d617bc2fc7a25888f`、`7e41a8375426bacd9255ce049f0ce395067d84343943f61965f0734e6b0c7b9b`、`f8b50a1e3508d70ecd73ef624d371cd41f0b39a5bb0b7cf5c7f6c89a09698d90`。这轮证明带来源的精确证据可用，**没有证明学出的门控胜过按来源奖励选择或全量合并**。Cohort v13 结果完成后另列。

## 已知限制与下一步

v10 在频谱的增益应归因于**公开结构化证据**；纯参数版尚未可靠学会把历史数值区域输出到下一题。扑克的 LoRA 有新的正向配对信号，但未做同题正确／错配历史的本轮复核，仍不能证明它选中了正确经验。数据库即便写入、增加当题历史或给文本教师，现有样本里都没有稳定加分。Cohort 的长 JSON 预算问题已定位并缓解；负分轨迹冷启动在完整 12 题上退步且仍有格式失败，安全回退与更多本领域有效训练样本仍待验证。

Sales Prediction、Codebase Adaptation 依赖 Docker socket；当前 `fengboyu` 不在 `docker` 组，`sudo -n docker info` 要求密码。用户确认暂时无法提供权限，所以两领域没有官方可评分结果。不会用绕开容器的替代任务冒充官方六领域成绩。

## 结构化证据如何通用化

v10 的“同名对象数组去重合并”只是一种有条件的算子，不能不经验证地推广到任意 JSON：频谱中旧对象可能代表持续可见的实体，Cohort 的标量预测则依赖当前人群和时间，直接复制历史值会错。更通用的记忆单元应保留 `(公开内容、schema 路径、来源题与动作、时间、反馈、内容哈希)`；让一个跨领域门控根据当前任务及历史证据选择 `忽略／精确保留／有条件聚合／调用 LoRA`，而不是由领域名指定规则。所有候选动作先经当前公开 schema 或命令校验，不合规回退并留下失败记录。

可把门控参数记为 $g_\theta(e,q,s,o)$，其中 $e$ 为带来源的历史证据，$q$ 为当前任务，$s$ 为当前动作 schema，$o$ 为可用操作；用同一后续任务的配对效用 $\Delta R=R(a^{+e})-R(a^{-e})$ 学选择，而非把历史动作当无条件正确标签。精确事实分支解决可追溯内容的复制，超网络 LoRA 分支学习动作分布与策略；训练时要分别报告各分支、混合方法、错误来源与无记忆对照。当前 v10 **尚未训练这个门控**，因此只能证明所测试协议中的结果，不能宣称结构化规则已跨全部领域通用。

所有原始轨迹、审核标注、权重及 JSON 结果留在忽略目录 `data/`、`results/`；仓库只上传代码与此报告。评测绑定检查点、模型配置、目标 `instance_id`／初始查询 SHA-256；v10 还绑定入口脚本 SHA-256。读取审计核对时间顺序、过去公开动作数组来源、写入触发、每题输出与总结；频谱另逐题用官方评分函数独立重算，以上已完成报告的审计均通过。
