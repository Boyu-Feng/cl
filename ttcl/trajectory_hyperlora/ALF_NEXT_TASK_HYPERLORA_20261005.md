# 从 ALFWorld 轨迹生成下一题 LoRA：训练游戏探索记录（2026-10-05）

## 目前判断

轨迹生成的 LoRA 在离线下一步动作模仿中改善了精确匹配，但原始完整环境配对运行降低成功率。加入两臂共同使用的可用命令约束后，51 道训练游戏从基模 24/51 升到 LoRA 29/51；另行划分的十一道开发游戏却是 **7/11 对 7/11**，增益和损失互相抵消。把离线模仿分数或训练游戏的小样本增益当作下一题效果会给出错误结论。目前没有证据支持始终挂载这个 LoRA，或声称已从特定轨迹抽象出可迁移技能。

## 数据和隔离

按冻结的 ALFWorld 计划，官方训练游戏有 144 个、官方评测游戏有 36 个，互不交叉。只从历史 `training/delta` 中选成功的训练游戏，找到 43 个；来源与目标是同一家族但不同的游戏。目标成功轨迹在真实环境中重放，逐步核查观察、可用命令、动作和获胜状态，留下 84 个候选动作。按目标游戏的稳定哈希拆为 62 个训练候选和 22 个开发候选；开发目标从不成为训练来源。一例因缺少不同的同家族训练来源而排除。

本地审核文件第一版批准 42 个动作（31 训练、11 开发），第二版批准 81 个动作（60 训练、21 开发）。每个审核项都绑定当前来源轨迹、目标轨迹、目标动作和完整输入内容的 SHA-256，训练前重新核对；不能按旧 history ID 复用标签。候选、审核文件、原始逐游戏结果与 checkpoint 均在仓库忽略路径中，未上传。

## 模型与代理指标

冻结 Qwen3-4B actor。来源是另一个已完成游戏的轨迹；编码器从轨迹的观察、动作、反馈关系生成末两层 `mlp.down_proj` 的 rank-4 LoRA `B` 因子，`A` 因子共享且可训练。actor 的下一题提示不含来源轨迹。只在训练候选上用已审核动作的序列交叉熵训练，开发候选仅作评估。第一版训练 124 步；第二版训练 240 步，种子均为 42。

| 审核版本 | 训练/开发动作 | 不挂 LoRA：开发动作精确匹配 | 挂来源 LoRA：开发动作精确匹配 | 可用命令匹配 |
| --- | ---: | ---: | ---: | ---: |
| 第一版 | 31/11 | 8/11 | 10/11 | 两臂均 10/11 |
| 第二版 | 60/21 | 17/21 | 19/21 | 不挂 20/21，挂载 21/21 |

精确匹配只是对历史成功轨迹中一个动作的模仿；别的可用动作可能同样合理。它不等于环境奖励。

## 完整环境配对

开发游戏按目标去重后共 11 道；同一游戏分别从重置状态跑不挂和挂载来源 LoRA，贪心解码，每臂最多 50 步，使用真实环境获胜反馈。两版开发结果如下。

| LoRA checkpoint | 基模成功 | 挂载成功 | 基模无效命令 | 挂载无效命令 |
| --- | ---: | ---: | ---: | ---: |
| 第一版，124 步 | 9/11 | 8/11 | 61 | 76 |
| 第二版，240 步 | 9/11 | 7/11 | 61 | 65 |

第二版在开发集的两道失败都是基模独有成功。失败轨迹里有重复选择无效命令等现象，说明参数更新会改变长程行动，离线单步动作改善不能保证回合获胜。

为了检查训练奖励是否同时有正、负信号，对第二版 checkpoint 另跑了 10 道训练游戏，每个任务家族按稳定顺序选两道，预算相同。基模成功 6/10，LoRA 成功 5/10；配对拆解为 LoRA 独有成功 1、基模独有成功 2、同成同败 7。无效命令总数为基模 65、LoRA 48。正例是 `pick_two_obj_and_place` 的 Pen→GarbageCan；两个负例分别是 AlarmClock→Desk 和 Bread→Microwave。这 10 道仅用于探索训练奖励，不能拿开发游戏的奖励训练门控。

固定强度扫描先用上述三个得失例，在相同游戏、来源和 50 步预算下把 LoRA 增量乘以 0.25。AlarmClock→Desk 由 LoRA 失败变成成功；Bread→Microwave 仍失败；Pen→GarbageCan 原先的 LoRA 独有成功消失。三题汇总基模 2/3、缩小 LoRA 1/3，后者 79 条无效命令。这是按已知得失例挑选的诊断，不是独立评估，且说明全局缩小强度无法同时处理这几个案例。

随后加了可用命令约束：每一步根据环境提供的 admissible commands 构造 token 前缀树，贪心解码只能形成其中一条完整命令；两个对照臂都使用同一约束。仍在上述三个得失例、原 LoRA 强度 1.0 上，基模成功 0/3、LoRA 成功 2/3，两臂无效命令均为 0。AlarmClock→Desk 和 Pen→GarbageCan 为 LoRA 独有成功，Bread→Microwave 两臂均失败。

补齐原先按每家族两道选定的其余七道训练游戏后，十题整体是**基模 4/10、LoRA 6/10**：LoRA 独有成功 2、基模独有成功 0、两臂同成 4、同败 4，双方无效命令均为 0。所有 10 对都有完整环境结果；两批运行的 checkpoint、候选清单、审核文件、步数上限和解码设置哈希/参数一致。这是训练游戏上的探索性正结果，不能直接推广到官方测试；同一约束也改变了基模原来的行动轨迹。

随后把相同协议扩至全部 31 道有审核动作的训练游戏，不再按家族限制两道：**基模 23/31、LoRA 25/31**，LoRA 独有成功 3、基模独有成功 1、同成 22、同败 5，双方仍无效命令 0。新增的一次正收益是照明查找 CD；新增的一次负迁移是 Laptop→Ottoman 放置。全部 31 对完整，三批输出采用同一 checkpoint、审核清单、50 步上限和约束设置。31 道中只有四道的奖励差非零，所以这批数据虽证实两种信号存在，仍不足以可靠训练高容量的奖励门控。

冻结这些设置后，对全部 11 道开发游戏跑相同约束协议。**基模 7/11、LoRA 7/11**，两臂无效命令均为 0；LoRA 独有成功 2、基模独有成功 2、同成 5、同败 2。正收益落在两道 `look_at_obj_in_light`，负迁移落在两道 `pick_and_place_simple` 的 Shelf 放置任务。训练十题没有任何负迁移，开发题却出现两次，说明仅依赖这十题的任务家族门控或全局强度选择会不稳。开发游戏没有用于 LoRA 权重训练；但约束解码是在看过原始开发失败后加入，因此这个开发集不能再视为完全未触碰的独立验证。

## 下一题奖励差门控试验

作为用户建议的最小配对奖励优化，令家族门控 $g_f\in\{0,1\}$ 表示是否给该类下一题挂 LoRA，仅以训练游戏最大化

\[
\sum_i g_{f(i)}\,[R_i(\mathrm{LoRA})-R_i(\mathrm{base})].
\]

差值为零时默认使用基模。任务家族从 actor **可见**的初始任务句子识别，并与游戏元数据核对，不把路径标签作为推理输入。用 31 道训练题拟合后，`look_at_obj_in_light` 和 `pick_two_obj_and_place` 各有一次净正奖励，门控开启；放置任务一正一负抵消，冷却、加热都没有差异，门控关闭。用已经跑过的开发两臂轨迹离线重组，得到基模 **7/11**、始终挂载 **7/11**、门控 **9/11**。这并非新的 11 道 rollout；episode 开始前选择一个已记录的臂，所以可以严格复算。

这个 9/11 **不是独立验证**：设计和选用家族门控之前，我们已经看过开发题的正负分布。训练集逐题留一交叉验证也只有门控 **22/31**，低于总是基模的 **23/31**，显示家族净正信号太少、决策不稳。它只说明配对奖励能指出有希望的使用范围，不能说明门控已经泛化。后续新增训练奖励以及未使用过的官方评测，才有资格检验冻结后的门控。

新增 20 道无历史成功动作标签的训练游戏全部完成，结果是基模 **1/20**、LoRA **4/20**；其中 LoRA 独有成功 3、基模独有成功 0、两臂同成 1、同败 16。冷却四题和加热四题均两臂同败；正向差值来自一题普通放置和两题双物体。合并原 31 道后，训练总计 **基模 24/51、LoRA 29/51**，LoRA 独有成功 6、基模独有成功 1、同成 23、同败 21；两臂所有命令均有效。51 道中仍只有 7 道有非零终局奖励差。

用全部 51 道训练题重新拟合上述固定形式的门控，照明、普通放置和双物体家族开启；冷却、加热关闭。训练集样本内为 **29/51**，逐题留一为 **26/51**，对照基模 **24/51**、始终挂载 **29/51**。但原开发 11 道的离线重组回到 **7/11**，与基模和始终挂载相同。新增训练正例让普通放置家族的净奖励转正，门控因而也启用开发集里的两个 Shelf 负例。这是明确的分布差异；不能拿 51 题样本内的 29/51 宣称已经泛化。

为检查“成功来自该来源轨迹”而非一般 LoRA 扰动，选所有基模失败、正确来源 LoRA 成功的已跑目标，换一条**同家族、不同游戏、已审核的训练成功轨迹**重新生成 LoRA，保持目标、checkpoint、有效命令约束和 50 步上限相同。共 8 条这样的正例，1 条 Pen 双物体任务没有第三条已审核训练来源，明确排除。其余 **7 条里，错来源仍成功 6 条；只有双物体 AlarmClock→Dresser 在错来源下失败**。同家族来源可互换本身也可能表示学到家族级技能，因此又在全部八个正例上改用**不同家族**的已审核训练来源：**8/8 仍然成功**，包括那道 AlarmClock→Dresser。这使“收益来自具体来源或家族技能”的解释都缺少对照支持，更符合跨家族共享参数偏置；并不证明所有来源残差都没有影响。没有把错来源失败记作基模收益，也没有用开发来源补齐同家族被排除项。

## 来源参数几何与公共 LoRA 消融

对 22 条已审核训练来源，直接计算生成 LoRA 的有效更新 $BA$ 的内积，不用未应用到模型的原始 latent 距离代替。全部来源的平均两两余弦为 **0.989**，跨家族平均 **0.986**；未中心化 Gram 矩阵的最大特征方向占 **99.34%** 能量。家族内部，照明、普通放置、冷却、加热的平均余弦分别约为 **0.9982、0.9997、0.9997、0.9997**；双物体两条来源为 **0.889**。这说明当前有效更新有很强公共分量，但并不意味着每个小残差都无效。唯一错来源导致成败变化的 AlarmClock→Dresser 案例，正确与错来源 LoRA 余弦也是 0.889；其他六条错来源仍成功的案例并非都完全相同。

把 22 条训练来源的生成因子逐层求平均，后续任务不指定来源，只挂这一份公共 LoRA。在相同 11 道开发游戏和 50 步约束协议下，基模 **7/11**、逐轨迹 LoRA **7/11**、平均 LoRA **8/11**。平均 LoRA 复现了两次照明正收益，并把 CreditCard→Shelf 的逐轨迹 LoRA 失败变成成功；另一个 Shelf 负例仍失败。这是已见开发集上的诊断，不能当成新的泛化证明，却直接表明多项行为变化不需要目标时指定轨迹。全部来源和平均因子的哈希、本地逐游戏轨迹保存在 ignored 结果目录。

## 冻结未见游戏的一次性检验

冻结模型、来源映射和上述公共平均因子后，在原始计划的全部 **36 道 `valid_unseen` 游戏**上做一次性对照。使用环境真实 `won` 计分及原计划 **30 步 / 64 输出 token** 预算；三个臂都用同一贪心、可用命令约束的 Qwen actor。历史 Delta-Mem 原实验的采样设置不同，因此以下是内部配对检验，**不是**对历史官方分数的重现。目标游戏和来源、文件哈希及输入内容另行审核绑定，评测奖励未进入训练。清洁家族没有已审核同家族训练来源，逐轨迹臂在该六题记为不支持，基模和公共 LoRA 仍全部运行。

| 家族，均为 6 题 | 基模成功 | 公共平均 LoRA 成功 |
| --- | ---: | ---: |
| 照明查找 | 4 | 4 |
| 普通放置 | 2 | 1 |
| 清洁放置 | 0 | 0 |
| 冷却放置 | 0 | 2 |
| 加热放置 | 1 | 1 |
| 双物体放置 | 0 | 2 |
| **全部 36 题** | **7** | **10** |

公共 LoRA 相对基模有 **6 题独有成功、3 题独有失败**，净差 +3/36；配对精确双侧符号检验 $p=0.508$，无法据此认定稳定提升。公共 LoRA 的正收益集中在两道 Bread 冷却题和两道双物体题，普通放置出现净负迁移。逐轨迹 LoRA 在有审核来源的 30 题中 **9/30**，同题基模 **7/30**、公共 LoRA **10/30**；逐轨迹臂没有任何一题独有胜过公共臂，反在一题 SoapBar→GarbageCan 上失去公共臂的成功。这是当前架构中“公共更新强、来源残差未证明有用”的直接证据，不等于否定轨迹到参数经验这条研究方向。

## 中心化来源残差：两次失败检验

针对上述公共分量主导的问题，冻结原编码器、actor 和公共平均 LoRA，只训练零初始化的线性头，将来源轨迹 latent 减去训练来源均值后映射为 LoRA 残差。训练时以已审核的下一题成功动作交叉熵为正目标，并让不同家族的错来源在同一目标上有较高损失；开发目标只用于离线评估。这是监督式元学习代理目标，**不是**使用环境奖励的 RL。两个 LoRA 层的公共因子固定，所有来源均为训练分割的成功轨迹。

旧版末两步审核集有训练 60、开发 21 个动作。120 步种子 42 的训练末 20 步，错来源与正确来源的平均交叉熵差达到 0.044，但开发集公共、原逐轨迹、中心化正确来源和中心化错来源全部 **19/21** 精确匹配。将来源排序权重提高、残差约束减小、训练延至 240 步后，种子 42/43 的训练损失差分别升至 0.142/0.196，开发集仍全部 **19/21**；正确来源反而有一次从有效命令变为无效命令。可见训练目标被优化了，但没有生成可检验的开发集来源收益。

为排查末两步动作过于集中，从同一批已冻结的成功训练轨迹中均匀抽取最多四个阶段动作，共 164 个未经审核的候选。逐项检查任务、动作前观察和可执行命令后，剔除探索绕路、无关物体操作和重复灯具设置；**另建**内容哈希绑定的审核文件，批准训练 48、开发 20 个动作。新标注与原末两步标注不按历史 ID 继承；重放和训练入口再次验证来源/目标 episode SHA-256、完整输入哈希、训练/开发分隔。新集覆盖取物、设备操作、放置和双物体任务，仍只是成功轨迹动作模仿，不能把每个历史动作都认定为唯一最优动作。

相同的 120 步中心化残差训练在种子 42/43 上，末 20 步错来源减正确来源交叉熵分别为 **0.147/0.058**；开发集基模 **17/20**、公共 LoRA **19/20**、原逐轨迹 LoRA **19/20**、正确来源残差 **19/20**、错来源残差 **19/20**。正确与错来源的开发集命令逐条相同。多阶段目标没有解除来源无效的问题；因此未用这两个新残差 checkpoint 跑完整环境，也未把它们说成有效的参数经验。原始候选、审核和结果在 ignored 目录，代码与此摘要可上传；模型权重仍不上传。

这组结果支持更具体的诊断：当前动作目标大多能从当前状态与任务句子直接确定，公共 LoRA 已达到较高模仿率；任意错来源的排序损失只强迫训练样本分开，并没有证明来源含有目标所需的信息。若继续训练，应先设计源轨迹能改变**同一类目标**最佳决策的配对任务，用真实下一题成功差验证来源因果作用，再考虑奖励训练 LoRA 生成头。单纯拉长训练或提高错来源损失没有证据会解决此问题。

所有完整游戏的原始动作、奖励、无效命令、来源和输入哈希保存在 ignored `results/trajectory_hyperlora/alf_next_task_warmstart_20261005/`。这些是小样本训练/开发探索，没有运行官方 ALFWorld test，也没有 CLBench 结果；两臂共享同一底座、目标重置和步数预算。

## 后续实验

新增 20 道目标从冻结的 144 个训练游戏中按固定哈希与家族配额选择，排除本轮历史成功轨迹目标、开发分割与官方评测；每道重新审核任务、成功训练来源和内容哈希，只用真实环境获胜奖励，没有迁移旧动作标签。公共 LoRA 与来源残差已分离，但现有监督目标未检出来源残差收益。下一版需要构造真正依赖来源信息的训练游戏配对，并让门控或残差读取当前任务、来源轨迹和动作阶段；也可与可检查的文本经验结合。应从不泄漏测试答案的任务进展取得更密的训练信号：51 道训练题只有七个非零终局奖励差，远不足以直接用高维策略梯度稳定更新整套 LoRA 因子。门控的选择和超参数必须由训练游戏确定，再在未使用过的目标上检验。先前完整游戏运行均采用配对臂相同的重置与预算；冻结未见游戏运行采用 30 步，训练/开发探索采用 50 步。
