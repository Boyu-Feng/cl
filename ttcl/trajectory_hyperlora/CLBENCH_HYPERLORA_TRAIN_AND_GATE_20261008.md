# CLBench 超网络训练与低于成功阈值的记忆写入实验

## 问题与协议

直接把 ALFWorld 超网络挂到 CLBench 时，频谱任务前四次官方分数约 0.21–0.25，却因官方 `success` 要求至少 0.5 而一次也没写入。扑克写入后的 LoRA 有时明显退化。此次保留原 ALFWorld 检查点与旧 CLBench 诊断，另写训练、门控与评测入口。训练仍是轨迹→LoRA 的超网络；测试从空参数记忆开始，每完成一题只根据自己的公开轨迹与官方回报决定是否写入。测试时超网络权重冻结，后续只挂累计因子，不给演员重读旧轨迹文本。

可评分领域为官方 blind spectrum monitoring、exploitable poker、database exploration。每题调用官方重置、动作 schema 与评分。seed 42、依原顺序，训练来源索引 0–5、开发索引 6–7，测试索引 8–19。后续探索性复测扑克索引 20–29；它进入官方日程中的另一个对手阶段 `loose_aggressive` / seed 43。基模 Qwen3-4B；训练与测试均在独立空闲 GPU 上完成，未中断其他实验。每题最多 64 回合、动作最多 512 token、上下文 16k，演员保留最近两轮历史。样本和日程是小规模研究协议，不等于 CLBench 六领域总成绩。

## 方法版本

- **原 ALF 检查点对照**：超网络仍只有 ALFWorld 训练；使用下述相同来源格式与写入门控，分离“CLBench 训练”和“接口改动”的影响。
- **v1 初试，保留失败**：从前一题公开轨迹生成 LoRA，用后一题正官方回报的模型动作做训练目标。扑克训练动作误删了其官方 schema 要求的 `thinking` 字段，目标 JSON 无效。因此 v1 的损失下降和回报退化只能当作接口错误的证据，不能当作有效训练结果。
- **v2 合法动作蒸馏**：来源编码仍去掉扑克的冗长 `thinking`，保留真正执行的动作、金额和反馈；目标动作则保留 schema 要求的字段。13 条训练动作、4 条开发动作均绑定各自原始轨迹、响应与官方回报哈希，目标通过官方 JSON schema 检查。在正官方回报的下一题上做行为蒸馏；这是回报筛选的监督学习，不是策略梯度。开发目标的 LoRA 交叉熵均值从 0.314 降到 0.141。
- **v3 成对回报训练**：固定训练段同一题，分别评分无 LoRA 和“前一题来源 LoRA”，取 `ΔR = R(LoRA) − R(无 LoRA)`。在两臂**首次有效动作分歧**处，正 `ΔR` 学 LoRA 臂动作，负 `ΔR` 学无 LoRA 臂动作；没有分数差的不造监督目标。扑克的非加注动作忽略未使用的 `amount` 字段，避免把 `CALL amount=5` 与 `CALL amount=null` 错认成决策分歧。训练段频谱 7 对均 `ΔR=0`；扑克训练段得到 4 个经审核目标（1 正、3 负），开发段 2 个（1 正、1 负）。从 v2 继续训练 60 步，开发动作交叉熵 0.351→0.334。该小样本不足以证明它学到稳定适用性。

**写入规则**使用同一个领域内自身已完成回合的官方回报：`R>0` 且不低于此前回报中位数才写入；第一次正回报可写。规则不依赖领域名、不把官方 `success` 当统一阈值，也允许“不写”。单独的源轨迹编码不包括私有终局标量，回报只给写入门控与训练标签使用。这个改动确实让频谱在低于 0.5 的正分之后写入；它不保证写入有益。

频谱测试 8–19 的三批各有两次低于官方成功阈值的参数写入，但目前这些后续动作/官方分数与无 LoRA 完全相同。数据库 12–15 里，v2 在最后一题从 0.600 提到 0.6667；另一批 16–19 没有正分来源写入。扑克 16–19 的收益与退化混在一起：v3 一题从 −0.5 提到 21，也有一题从 −1 降到 −13。20–29 的 v2 是 5 题正增益、5 题持平、0 题退化；v3 是 3 题正增益、6 题持平、1 题退化。虽然这个新对手阶段更严格，这仍是探索性小样本，尚未证明整个 CLBench 稳定提升。

v1 接口错误版在 8–11 扑克上为无 LoRA 1.750、LoRA −0.875；相同写入规则下原 ALF 检查点为 1.500。这一版保留为反例，不纳入有效版本比较。

**持续更新消融**：20–29 的 v2 允许逐题写入，共写 4 次；只允许首题写入 1 次的同检查点对照也是 1.750，10 题执行动作轨迹全部一致。因此这批新阶段收益来自**首条来源生成并挂载 LoRA**，没有证据表明后续三次写入额外改善了动作。它仍从空历史开始，但不能拿这批结果证明“持续更新”有效。

另做了**复用已见题目索引的探索性跨阶段诊断**，从索引 16 空记忆开始连续跑到 25，横跨 `calling_station`→`loose_aggressive`：无 LoRA 均分 1.30，v2 持续写入 3 次为 3.35，只保留首条写入为 3.30。持续写入在一手使 2.0 降为 −0.5，在另一手使 −1.0 提到 2.0；净差只有 +0.05/题。进入新对手阶段后，三条来源的读取权重几乎都是 `1/3`，说明当前任务键没有明显区分这些来源；新增参数混合既可能帮助也可能干扰。该诊断重复使用了前面看过的索引，不计作新的独立测试。

## 现在能判断什么

1. **空记忆的直接原因已解决**：官方 `success` 是领域特定的二值指标，不能充当通用经验价值函数。新门控用自身连续回报的运行中位数，让频谱正分轨迹可以写入，并保留不写选项。
2. **有 CLBench 训练收益的局部信号**：在第二个扑克对手阶段，同批无 LoRA 0.00、原 ALF 检查点 0.75、v2 达到 1.75，且 v2 逐题没有负增益。v2 在 3 手牌上比原检查点得分更高；其中两手原检查点 `FOLD` 而 v2 继续参与并获正回报。v3 也是正向但比 v2 低。首条写入消融说明这批收益无需后续持续写入。
3. **写入与真正学到经验是两回事**：频谱虽写入但训练/测试都未看到分数改变。当前正分只说明报告有部分重合，没有标出哪些持久频点被漏掉；单条轨迹加终局标量给超网络的信用信息不足。要改进频谱，需要更丰富的自身探索/反馈与可检验的后续收益，而非继续降低阈值。
4. **成对回报是更贴近目标的信号，但本次数据太少**：v3 仅四条扑克训练分歧；它在 16–19 胜过 v2，却在 20–29 输给 v2。因此不能把少量 `ΔR` 样本训练误当成已验证的通用 RL 方案。若要验证持续更新，需要训练会预测“这条来源对当前题是否有益”的读取门控，并在新的跨阶段顺序测试中与只留首条的版本比较。

Cohort studies 的长 JSON/上下文预算问题仍未解决，本轮没有训练和完整配对评分；Sales prediction、Codebase adaptation 依赖当前不可访问的 Docker socket，也未运行。结论限于三领域的上述小规模协议，不能宣称六领域通用提升。
