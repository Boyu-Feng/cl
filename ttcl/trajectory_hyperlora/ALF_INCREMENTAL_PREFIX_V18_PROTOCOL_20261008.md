# 完整历史前缀的连续 LoRA 写入：预先冻结协议

[v14 来源—目标题池](ALF_INCREMENTAL_POOL_V14_PROTOCOL_20261008.md)和[v17 条件门控](ALF_INCREMENTAL_GATE_V17_PROTOCOL_20261008.md)只比较一条旧成功轨迹与两条成功轨迹的等权均值。它们不能说明第三条及以后自身成功轨迹的真实增量效用。本协议在读取该类结果前固定四次**真实按时间顺序**的后续写入：序列 0 的 2→3、3→4、4→5，以及序列 6 的 2→3。两个序列的 1→2 已由 v14 覆盖，不重复采集。四次转移与全部 78 道目标题交叉，共 312 个写入／冻结配对、624 个计划环境回合；60 道训练题形成 240 对，18 道目录隔离开发题形成 72 对。目标题和来源均沿用 v14，选择规则不读取 v14 或 v18 的回报。

每条来源是冻结 Qwen 编码器对自身已完成且官方 `won` 的轨迹提取的全局向量、动作反馈差分向量及超网络记忆字段；轨迹不是新生成的。对完整旧前缀 $\tau_{1:n}$，冻结臂使用其精确运行平均 $m_n=n^{-1}\sum_{i=1}^{n}E(\tau_i)$，写入臂仅加入下一条成功轨迹，使用

\[
m_{n+1}=m_n+\frac{E(\tau_{n+1})-m_n}{n+1}.
\]

三个向量／字段通道均应用同一更新。两臂保持相同目标题、冻结 Qwen3-4B、原超网络、v5 残差修正、合法动作约束、50 步与每步 64 token、两轮动作历史及两次重复抑制；没有测试时梯度更新。输入给演员的只有压缩参数记忆和当前任务，不重读完整来源文字。每个分片由 `target_id % 3` 决定，104 对，其中训练 80、开发 24；三个分片仍只在此前 GPU 作业完成且相应显卡空闲时运行，不抢占其他实验。

新冻结标注绑定全部旧前缀来源记录哈希、下一条来源记录、目标题游戏内容、v14 池、检查点、残差权重、前缀长度和写入权重。`freeze_alf_incremental_prefix_v18.py check` 必须与标注逐字段一致。标注位于 Git 忽略路径，SHA-256 为 `c257d1757891482773419d95ce5648ef2f19172af70f4021f8a90c80753878db`；旧 v14 池 SHA-256 为 `a7f15db7f6bc4d26218427816fbd872fc99f165a0d811cfc5ea17f09800926cc`。采集器 `collect_alf_incremental_prefix_v18.py` 支持内容校验、分片和同一已冻结输入上的断点续跑。原始每一臂必须经 `audit_alf_incremental_prefix_v18.py` 在官方原环境逐动作重放，且核对来源、目标题、完整前缀向量、两臂初态和终局回报。运行结果与原始标注留在 Git 忽略路径；代码和审计后的摘要上传。

主要分析单位是**整道目标题**，同题四种前缀转移不能当成四道独立题。训练与开发分开报告每个前缀长度的冻结／写入成功、写入独赢／冻结独赢、改变动作轨迹的比例，并按六类目标给出方向。`analyze_alf_incremental_prefix_v18.py` 预先固定 10,000 次、种子 20261008 的家族分层整题 bootstrap；同一道题的四次转移一起重采样。2→3 来自两个来源序列，3→4 和 4→5 仅来自序列 0，因此**前缀长度与来源序列混杂**，不同长度的差异不能解释成纯粹长度效应；区间也不代表新来源或新任务顺序的泛化保证。最直接的检验是：在这些实际完整旧记忆状态上，新写入能否稳定优于冻结。若没有，不能把 v14 的 1→2 局部收益称为持续学习收益。

本实验仍是固定自身成功来源库与目标交叉的**训练域反事实**，不是各方法从空历史出发自行采集后续轨迹的闭环。即使 v18 显示持续前缀的正效用，论文主张仍需冻结门控训练、独立官方 `valid_seen`／`valid_unseen` 多顺序、自身闭环更新、固定首条／无 LoRA／等预算原始文本与总结／原生 MemRL 及在线 SGD 对照。开发题只允许对预先冻结的候选评一次，不能反复调到其结果上。
