# 官方训练集自身成功轨迹：后见蒸馏资料准备

为减少现有反馈残差实验只有 8 条独立来源、终局奖励优势稀疏的问题，新增 `prepare_alf_replay_verified_self_bank_v1.py`，从既有、内容哈希固定的官方 ALFWorld `train` 域 240 道回合报告里，仅取**无记忆 `base` 臂**自己完成且官方 `won=1` 的轨迹。它没有调用新演员，也没有从验证或测试集读取成功标签。历史报告使用 30 步、每步 64 token 的预算，与目前 50 步演员协议不同，作为训练资料必须明确记录，不能混成同一评测结果。

筛出 **57 条不同游戏的正奖励轨迹**。用原 PDDL 游戏逐条重置、重放每个已执行命令，检查命令在当步 admissible 列表中、环境反馈与记录逐字一致、终局确实完成。得到 **633 个动作—反馈标注**，平均 11.11 步／轨迹，重放失败 0。每个标注的输入哈希绑定游戏文件哈希、完整来源回合哈希、当步观察、可用命令、执行动作、环境反馈与终局标记。另用 `audit_alf_replay_verified_self_bank_v1.py` 独立重算全部 57 条来源与 633 个标注的绑定，审核通过。原始标注保存在 Git 忽略的 `data/annotations/alf_self_base57_replay_reviewed_20261007.json`；摘要、方法与复现代码入仓库，原始数据和模型权重不强制上传。

类别覆盖仍不均衡：`look_at_obj_in_light` 23、`pick_and_place_simple` 21、`pick_clean_then_place_in_recep` 1、`pick_cool_then_place_in_recep` 1、`pick_heat_then_place_in_recep` 4、`pick_two_obj_and_place` 7。它能支持小规模轨迹编码／动作软标签实验，尚不足以声称所有六类都能学会。任何新配对目标还要按这些**新内容哈希**重新定义训练／验证拆分；不得沿用旧 history ID 的标注。训练时可让冻结教师在后续训练题状态看到来源轨迹，蒸馏给只挂载生成 LoRA 的学生，再在未见游戏的单次在线题序检验；这只是后续实验方案，当前 57 条资料本身没有证明新方法有效。

初版 `prepare_alf_self_future_pairs_v1.py` 曾冻结 46 个 `train` 域训练游戏、11 个内部开发游戏，以及 264／66 个训练／开发配对；随后主动交叉核对旧检查点训练标签，发现 **4 个开发游戏与当前旧检查点的训练目标重合**。这份初版记录保留作失败审计，**不可用于泛化评估**。

修正版 `prepare_alf_self_future_pairs_v2.py` 把**最后一阶段**旧检查点训练标签文件的哈希写进每个新配对绑定，让内部开发游戏不与该阶段的 33 个目标重合。当前 57 条来源重分为 **50 个训练游戏、7 个开发游戏**；来源轨迹只从训练游戏取得，且与目标题不同。每题按首／中／末三个已验证动作状态、每状态两条同类但不同游戏的来源轨迹创建新内容绑定，共 **288 个训练配对、42 个开发配对**，独立 `audit_alf_self_future_pairs_v2.py` 的内容和直接标签拆分审核通过。类别只影响数据抽样，生成器本身不接收类别槽。**21 条 `pick_and_place_simple` 自身成功轨迹全都曾进入最后阶段旧检查点训练标签**；`pick_clean`、`pick_cool` 各只有一条轨迹，无法构造类内跨题配对。

进一步追溯祖先检查点训练候选集发现，**这 57 个游戏全部包含在上游 `train600` 候选中**。因此 v2 文件名中的 `checkpoint_disjoint` 只指最后阶段标签，**不代表对完整旧检查点血缘独立**。这批 288/42 配对仅可用于新生成器训练和受污染的开发调试，不能作为泛化测试；要评价全部六类并作论文主张，必须补充新自身回合并在未见的官方验证／测试题单上评估。v2 配对标注存放于 Git 忽略的 `data/annotations/alf_self_future_pairs_v2_checkpoint_disjoint_reviewed_20261007.json`，不能与已有 8×18 奖励矩阵结果混为一谈。
