# 从空历史出发的官方 ALFWorld 方法自身闭环对照

此前 [v6 同来源对照](ALF_FRESH_SEEN_SHARED_ONLINE_V6_20261007.md)让各方法使用同一条无记忆演员采集的成功历史，适合隔离记忆读取方式，却不能衡量不同方法改变行动后会采集到什么后续轨迹。本协议固定**每个方法独立从空历史开始**的顺序实验；各方法每题只见此前自己完成的任务和轨迹，当前题的反馈只在本题行动中可见。

题单沿用在本轮结果前已冻结的 `alf_valid_unseen_multiorder_v10_plan.json`：官方 `valid_unseen` 三条互不重叠的 30 题顺序，各含六类×五题，共 90 道游戏、每方法 90 次单回合尝试。所有这 90 道游戏此前在本地旧报告中出现过，因此这是**预先固定顺序的探索性官方评测，不是新游戏盲测**。新标注 `freeze_alf_onpolicy_v19.py` 为四方法×三顺序×30 题重新绑定游戏文件、模型检查点、v5 残差、演员预算和输入内容；冻结标注 SHA-256 为 `50ebe9dc068ecc10c14c73672c5951978b769c9baf07511be1223494763ad8fa`，保留在 Git 忽略的 `data/annotations/`。运行时每条记录另外绑定截至当前题的本方法**自身成功轨迹记录哈希链**，不能从历史 ID 复用标签。

四个冻结方法共用 Qwen3-4B、确定性合法命令演员、50 步／每步 64 token／两轮动作历史／两次重复抑制与同一顺序；LoRA 方法还共用原超网络和 v5 残差，无测试时梯度更新：

1. `base`：不使用跨题记忆。
2. `continuous_success_mean`：仅官方获胜的自身轨迹进入来源编码；每次写入运行均值，下一题由超网络生成条件 LoRA。
3. `fixed_first_success`：只接纳首次自身获胜轨迹，之后保持该参数记忆；它是连续写入独立贡献的关键对照。
4. `own_success_raw_text`：把截至当前题的自身成功轨迹原始记录作为提示文本，统一截到 2048 source tokens；没有 LoRA。

每个方法的轨迹**由自身策略产生**，不能把它们当成同一历史的互换对照。`continuous_success_mean` 与 `fixed_first_success` 的差是完整反馈回路的总效应，包含不同动作导致的后续成功来源变化；已完成的共同来源 v6 对照补充了控制来源后的局部效应。原始文本与 LoRA 使用同一个“只有自身官方成功可进入跨题记忆”的证据规则和相同源长度上限，但两者的编码成本、每步提示 token 和模型训练历史不同，必须分别报告；单凭这个文本对照不能穷尽 MemRL、学习型文本总结或在线 SGD 的竞争力。

采集入口 `evaluate_alf_onpolicy_v19.py --order {0,1,2} --method {base,continuous_success_mean,fixed_first_success,own_success_raw_text}`。每个方法×顺序独立保存 30 条完整轨迹、成功来源记录、写入决策、来源向量哈希、实际文本和动态输入哈希；失败也保留。`audit_alf_onpolicy_v19.py` 必须逐动作在原 ALFWorld 环境重放全部 360 条回合，核对获胜来源的因果哈希链、固定首条规则及原始文本拼接／截断。所有游戏内容和演员、残差模型哈希在运行前后都要一致。三份 v14 GPU 作业结束、显卡确认为空闲前不运行 v19；不占用其他用户的卡。

报告逐顺序及六类的官方成功数、连续写入次数、逐题连续与固定首条的新增／退化、各臂来源长度和文本 token。三条顺序是主要重复单位，不能把 360 回合当作 360 个独立随机种子。若连续均值没有在多个顺序中超过固定首条，则仍无持续更新净收益；即使超过，也要继续检验新模型条件门控、自身闭环来源置换、原生 MemRL、强文本总结与在线 SGD，才可主张参数经验更好。v17 门控只训过 1→2 条来源，**不直接嫁接到本实验的第三条及之后写入**；先等 v18 完整前缀数据验证其适用范围，再另建新版本。
